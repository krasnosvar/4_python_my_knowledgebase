# Лямбда-функции

В Python функцию можно передать в другую функцию как обычное значение —
так же, как число или строку (подробно это разбирается в
[03_first_class_functions_and_closures.md](./03_first_class_functions_and_closures.md)).
Часто такая функция нужна ровно в одном месте и состоит из одного
выражения — писать ради неё полноценный `def` с именем избыточно. Для этого
есть `lambda`: короткая безымянная функция прямо «по месту».

```python
def square(x):
    return x ** 2

square = lambda x: x ** 2   # то же самое, записанное через lambda
square(4)                   # 16
```

Слева от `:` — параметры (как в скобках у `def`), справа — одно выражение,
результат которого функция возвращает. Слово `return` не пишется.

## Зачем это нужно: функция как аргумент

Самый частый случай — встроенная функция `sorted()` с параметром `key`.
`key` — это функция, которую `sorted` вызовет для каждого элемента, чтобы
понять, по какому значению его сравнивать:

```python
words = ["банан", "яблоко", "киви"]
sorted(words)                          # по алфавиту: ['банан', 'киви', 'яблоко']
sorted(words, key=len)                 # по длине: ['киви', 'банан', 'яблоко']
sorted(words, key=lambda w: w[-1])     # по последней букве
```

`len` — уже готовая функция, её можно передать как есть. А «последняя
буква» — нет такой готовой функции, и `lambda` позволяет описать её прямо в
вызове.

Ещё две встроенные функции, принимающие функцию аргументом:

* `filter(функция, коллекция)` — оставляет элементы, для которых функция
  вернула истинное значение;
* `map(функция, коллекция)` — применяет функцию к каждому элементу.

Обе возвращают не список, а «ленивый» объект (подробно — в разделе
[4_iterators_generators](../../4_iterators_generators/README.md)), поэтому
для просмотра результата его оборачивают в `list(...)`:

```python
numbers = [1, 2, 3, 4, 5, 6]
list(filter(lambda x: x % 2 == 0, numbers))   # [2, 4, 6]
list(map(lambda x: x * 10, numbers))          # [10, 20, 30, 40, 50, 60]
```

На практике вместо `map`/`filter` в Python чаще пишут comprehension
(`[x * 10 for x in numbers]`), но читать чужой код с ними нужно уметь.

Составной ключ сортировки — кортеж: сначала сравнивается первый элемент,
при равенстве — второй:

```python
people = [
    {"last_name": "Иванов", "first_name": "Пётр", "age": 30},
    {"last_name": "Иванов", "first_name": "Анна", "age": 25},
]
sorted(people, key=lambda p: p["age"])
sorted(people, key=lambda p: (p["last_name"], p["first_name"]))
```

## Ограничение: только одно выражение

Тело лямбды — ровно одно выражение, значение которого неявно возвращается.
Внутри лямбды нельзя написать:

* присваивание (`x = 1`) — оператор `:=` (см.
  [03_comprehensions.md](../../1_python_fundamentals/05_collections/01_theory/03_comprehensions.md))
  технически обходит это, но это скорее исключение;
* несколько инструкций;
* `if`/`else` как отдельные строки — только условное выражение в одну
  строку: `a if условие else b`;
* циклы, `try`/`except`, `with`.

Это не временное неудобство, а замысел: лямбда — компактное встраиваемое
выражение, а не замена `def`.

## Почему PEP 8 не рекомендует присваивать лямбду имени

PEP 8 (официальное руководство по стилю Python, правило E731) советует не
делать так:

```python
# Плохо
f = lambda x: x + 1

# Хорошо
def f(x):
    return x + 1
```

Причины:

* **Имя функции в сообщении об ошибке.** Функция, объявленная через `def`,
  при ошибке показывается под своим именем (`f`); лямбда всегда называется
  `<lambda>`, и если таких несколько — отлаживать труднее.
* **Документируемость.** У `lambda` нет места для docstring.
* **Расширяемость.** Если логику потом нужно расширить (добавить проверку,
  несколько строк), `def` не придётся переписывать, а лямбду — придётся.

Итог: используйте `lambda` как безымянный аргумент «на лету» (`key=` и
подобные места), а как только функции нужно имя — переходите на `def`.
