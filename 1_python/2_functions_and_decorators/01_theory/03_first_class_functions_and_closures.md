# Функции как объекты первого класса и замыкания

В Python функции — обычные объекты: их можно присвоить переменной,
передать как аргумент, вернуть из другой функции, положить в список или
словарь. Это фундамент, на котором строятся декораторы
([04_decorators_basics.md](./04_decorators_basics.md)), колбэки и
функциональный стиль.

```python
def greet(name):
    return f"Привет, {name}"

say = greet          # без скобок: не вызов, а сама функция
say("Аня")           # 'Привет, Аня'
```

## Функции высшего порядка

Функция высшего порядка — функция, которая принимает другую функцию как
аргумент и/или возвращает функцию как результат.

```python
def apply_twice(func, value):
    return func(func(value))

apply_twice(lambda x: x * 2, 3)  # 12
```

Встроенные примеры уже встречались в [01_lambdas.md](./01_lambdas.md):
`map`, `filter`, `sorted(key=...)`. Ещё одна — `functools.reduce(функция,
коллекция)`: «сворачивает» коллекцию в одно значение, применяя функцию к
накопленному результату и следующему элементу
(`reduce(lambda acc, x: acc + x, [1, 2, 3])` → `6`). `functools` — модуль
стандартной библиотеки, его подключают через `import` (см.
[08_modules_and_imports](../../1_python_fundamentals/08_modules_and_imports/README.md)).

## Замыкания (closures)

Функцию можно объявить внутри другой функции. Замыкание — это такая
вложенная функция, которая «помнит» переменные из внешней функции даже
после того, как внешняя функция уже завершила выполнение.

```python
def make_multiplier(factor):
    def multiplier(x):
        return x * factor  # factor берётся из внешней функции
    return multiplier

double = make_multiplier(2)
double(5)  # 10
```

`make_multiplier(2)` давно отработала, но `double` всё ещё знает, что
`factor` равен `2`.

### Что именно захватывает замыкание

Ключевой и неочевидный момент: замыкание захватывает **не значение**, а
**саму переменную** (точнее — ячейку памяти, cell object), в которой это
значение лежит. Посмотреть на это можно через служебный атрибут
`__closure__` (атрибуты с двойными подчёркиваниями Python создаёт сам):

```python
double.__closure__[0].cell_contents  # 2
```

Если внешняя переменная изменится после создания замыкания, но до его
вызова, замыкание увидит новое значение — потому что оно смотрит на ту же
ячейку, а не на копию.

## `nonlocal`

По умолчанию присваивание внутри вложенной функции создаёт **новую
локальную переменную**, а не изменяет переменную из внешней функции. Чтобы
явно указать, что нужно изменять именно внешнюю переменную (для чтения
`nonlocal` не нужен), используется `nonlocal`:

```python
def make_counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    return increment
```

Без `nonlocal` строка `count += 1` внутри `increment` вызвала бы ошибку
`UnboundLocalError` (что такое ошибки-исключения — см.
[07_exceptions](../../1_python_fundamentals/07_exceptions/README.md)):
`count += 1` — это одновременно чтение и присваивание, а присваивание без
`nonlocal` делает `count` локальной переменной `increment` ещё до того, как
до неё дойдёт выполнение.

## Классическая ловушка: позднее связывание в цикле

```python
funcs = [lambda: i for i in range(3)]
[f() for f in funcs]  # [2, 2, 2], а не [0, 1, 2]!
```

Причина: тело лямбды не выполняется в момент создания — оно лишь
запоминает переменную `i`. К моменту вызова всех лямбд цикл уже завершился,
и `i` равно последнему значению (`2`). Все три лямбды делят одну и ту же
ячейку `i`.

### Способ 1 — зафиксировать значение через аргумент по умолчанию

Значения по умолчанию вычисляются **один раз**, в момент определения
функции — так «текущее значение» можно зафиксировать без отдельной функции:

```python
funcs = [lambda i=i: i for i in range(3)]
[f() for f in funcs]  # [0, 1, 2]
```

### Способ 2 — явная фабрика замыканий

```python
def make_lambda(i):
    return lambda: i

funcs = [make_lambda(i) for i in range(3)]
[f() for f in funcs]  # [0, 1, 2]
```

Здесь каждое замыкание получает собственный параметр `i` — новую ячейку
при каждом вызове `make_lambda`, а не общую переменную цикла.

> Эта же ловушка проявляется не только с лямбдами, но и с обычными
> вложенными функциями и колбэками, создаваемыми в цикле — механизм всегда
> один и тот же.
