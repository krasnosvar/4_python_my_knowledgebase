# Декораторы с аргументами

Обычный декоратор принимает ровно один аргумент — оборачиваемую функцию.
Если декоратору нужны собственные параметры (`@retry(times=3)` — «повторить
до трёх раз»), требуется ещё один уровень вложенности — **фабрика
декораторов**.

## Три уровня вложенности

Пример ниже повторяет вызов функции, если она завершилась ошибкой. Ошибки
в Python — это исключения, их перехватывают через `try`/`except`, а заново
выбрасывают через `raise` (см.
[07_exceptions](../../1_python_fundamentals/07_exceptions/README.md)).

```python
def retry(times):                      # уровень 1: фабрика — принимает аргументы декоратора
    def decorator(func):               # уровень 2: сам декоратор — принимает функцию
        def wrapper(*args, **kwargs):  # уровень 3: обёртка — принимает аргументы вызова
            last_exc = None
            for _ in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception as exc:
                    last_exc = exc     # запомнили ошибку и пробуем снова
            raise last_exc             # все попытки неудачны — отдаём последнюю ошибку
        return wrapper
    return decorator

@retry(times=3)
def flaky():
    ...
```

Разбор по шагам: `@retry(times=3)` сначала вызывает `retry(3)`, которая
возвращает `decorator`. Именно `decorator` затем применяется к `flaky` —
так же, как обычный декоратор без аргументов. То есть `@retry(times=3)`
эквивалентно `flaky = retry(3)(flaky)`.

Каждый уровень — это замыкание: `decorator` захватывает `times` из
`retry`, а `wrapper` захватывает `func` из `decorator`.

## Декораторы на основе класса

> Этот подраздел использует классы — они разбираются в разделе
> [3_oop](../../3_oop/README.md). Если классы пока незнакомы, пропустите
> его и вернитесь после `3_oop`. Коротко: `class` описывает новый тип
> объектов, `__init__` срабатывает при создании объекта, `self` — сам
> этот объект, а метод `__call__` позволяет «вызывать» объект как функцию.

Вместо трёх вложенных функций декоратор с состоянием можно реализовать
классом с методом `__call__`, который делает экземпляр класса вызываемым
(callable):

```python
class CountCalls:
    def __init__(self, func):
        self.func = func
        self.calls = 0

    def __call__(self, *args, **kwargs):
        self.calls += 1
        return self.func(*args, **kwargs)

@CountCalls
def greet():
    ...

greet()
greet.calls  # 1
```

Такой подход удобен, когда декоратору нужно хранить состояние между
вызовами (счётчики, кэш) — состояние естественно живёт в атрибутах
объекта, а не в замыкании.

## Параметризованные декораторы из стандартной библиотеки

Два показательных примера из модуля `functools`, устроенных именно как
фабрики декораторов:

* **`functools.lru_cache(maxsize=...)`** — запоминает результаты вызовов
  по аргументам (мемоизация «из коробки»): повторный вызов с теми же
  аргументами не вычисляется заново. `maxsize` — параметр фабрики, точно
  как `times` у `retry`.
* **`functools.singledispatch`** — превращает обычную функцию в
  «универсальную», выбирающую реализацию по типу первого аргумента;
  дополнительные реализации регистрируются через `@func.register(SomeType)`,
  что само по себе тоже декоратор.

```python
from functools import lru_cache, singledispatch

@lru_cache(maxsize=128)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

@singledispatch
def render(value):
    raise NotImplementedError

@render.register(int)
def _(value):
    return f"int: {value}"
```

`fib` здесь вызывает саму себя — это рекурсия, она подробно разбирается в
[8_algorithms_dsa](../../8_algorithms_dsa/README.md); для понимания
`lru_cache` достаточно того, что без кэша `fib(35)` вычисляет одни и те же
значения миллионы раз, а с кэшем — по одному разу.
