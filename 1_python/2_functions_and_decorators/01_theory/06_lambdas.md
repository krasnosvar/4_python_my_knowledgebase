# Лямбда-функции

`lambda` создаёт анонимную функцию из **одного выражения**:

```python
square = lambda x: x ** 2
```

## Ограничение: только выражение

Тело лямбды — ровно одно выражение, значение которого неявно возвращается. Внутри лямбды
нельзя разместить:

* присваивания (`x = 1`) — начиная с Python 3.8 есть обходной путь через "морж" `:=`, но это
  скорее исключение, подтверждающее ограничение;
* несколько инструкций через `;`;
* `if/else` в виде оператора (только тернарное выражение `a if cond else b`);
* циклы, `try/except`, `with`.

Это принципиальное ограничение синтаксиса, а не временное неудобство: лямбда в Python
задумана как компактное встраиваемое выражение, а не как замена `def`.

## Легитимные случаи использования

Лямбда уместна там, где нужна короткая одноразовая функция "по месту", обычно как аргумент
другой функции:

```python
sorted(people, key=lambda p: p["age"])
sorted(people, key=lambda p: (p["last_name"], p["first_name"]))  # составной ключ
list(filter(lambda x: x % 2 == 0, numbers))
```

## Почему PEP 8 не рекомендует присваивать лямбду имени

PEP 8 (правило E731) явно советует не делать так:

```python
# Плохо
f = lambda x: x + 1

# Хорошо
def f(x):
    return x + 1
```

Причины:

* **Имя функции в трейсбеке.** Функция, определённая через `def`, попадает в трейсбек под
  своим именем (`f`); лямбда, присвоенная переменной, всё равно называется `<lambda>` —
  отладка усложняется, особенно если таких лямбд в коде несколько.
* **Документируемость.** У `lambda` нет места для docstring — только само выражение.
* **Читаемость и расширяемость.** Если логику потом нужно расширить (добавить проверку,
  логирование, несколько строк), `def` не потребует переписывания синтаксиса, а лямбда —
  потребует, так как для неё этого физически некуда вставить.

Итог: используйте `lambda` как безымянный аргумент "на лету" (`key=`, `default=` в колбэках
и т. п.), а как только функции нужно имя — переходите на `def`.
