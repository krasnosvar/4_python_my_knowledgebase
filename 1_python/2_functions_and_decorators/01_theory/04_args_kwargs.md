# `*args` и `**kwargs`

## Механика упаковки

При объявлении функции `*args` собирает все лишние позиционные аргументы в **кортеж (tuple)**,
а `**kwargs` — все лишние именованные аргументы в **словарь (dict)**:

```python
def f(*args, **kwargs):
    print(args)    # tuple
    print(kwargs)  # dict

f(1, 2, a=3, b=4)  # (1, 2)  {'a': 3, 'b': 4}
```

Имена `args`/`kwargs` — соглашение, а не требование языка: важны именно символы `*` и `**`.

## Позиционные-только и именованные-только параметры (PEP 570)

Символы `/` и `*` в сигнатуре функции задают границы:

```python
def f(a, b, /, c, d, *, e, f):
    ...
```

* параметры до `/` — **только позиционные** (нельзя передать как `a=1`);
* параметры после `*` — **только именованные** (нельзя передать позиционно);
* параметры между `/` и `*` — обычные, можно и так, и так.

Позиционные-только параметры полезны в API, где имя параметра — деталь реализации, которую
нельзя фиксировать как часть публичного контракта (типичный случай — встроенные функции вроде
`len(obj, /)`). Именованные-только параметры делают вызов самодокументируемым и защищают от
случайной путаницы порядка похожих по смыслу аргументов (`connect(host, port, *, timeout=30)`
не даст случайно передать таймаут как позиционный аргумент).

## Распаковка при вызове

Тот же синтаксис работает и в обратную сторону — для распаковки готовой последовательности
или словаря в аргументы вызова:

```python
args = (1, 2)
kwargs = {"a": 3, "b": 4}
f(*args, **kwargs)  # эквивалентно f(1, 2, a=3, b=4)
```

Это часто используется для передачи "как есть" аргументов дальше — в родительский `__init__`
через `super().__init__(*args, **kwargs)`, либо в обёртке декоратора.

## Почему `**kwargs` обязателен для "прозрачного" декоратора

Если обёртка декоратора принимает только конкретные, заранее известные аргументы, декоратор
перестаёт работать с функциями другой сигнатуры:

```python
def bad_decorator(func):
    def wrapper(x):       # жёстко зашитый один аргумент
        return func(x)
    return wrapper
```

Такой декоратор сломает любую функцию, принимающую два аргумента или именованные параметры.
Чтобы декоратор был универсальным и "прозрачным" — работал с функцией **любой** сигнатуры —
обёртка должна вслепую принимать и пробрасывать всё через `*args, **kwargs`:

```python
def good_decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```

Это стандартный шаблон для любого универсального декоратора (логирование, тайминг, retry,
кэширование), поэтому он появляется практически в каждом примере декоратора в этом разделе.
