# Декораторы: основы

Декоратор — это функция высшего порядка (см.
[03_first_class_functions_and_closures.md](./03_first_class_functions_and_closures.md)),
которая принимает функцию и возвращает функцию — обычно обёртку вокруг
оригинала. Зачем: добавить к функции общее поведение (логирование, замер
времени, повтор при ошибке, кэширование), не меняя её код и не копируя
одно и то же в каждую функцию. Синтаксис `@decorator` — просто
«синтаксический сахар».

## Десахаривание `@decorator`

```python
@my_decorator
def greet():
    print("Привет")
```

полностью эквивалентно:

```python
def greet():
    print("Привет")

greet = my_decorator(greet)
```

То есть после выполнения этого кода имя `greet` указывает уже не на
исходную функцию, а на то, что вернул `my_decorator(greet)` — как правило,
другую функцию-обёртку.

## Минимальный декоратор

```python
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print("До вызова")
        result = func(*args, **kwargs)
        print("После вызова")
        return result
    return wrapper
```

`wrapper` — замыкание: оно захватывает `func` из внешней функции
`my_decorator`. `*args, **kwargs` позволяют обёртке принять любые
аргументы и передать их дальше (см. [02_args_kwargs.md](./02_args_kwargs.md)).

## Почему декоратор «ломает» метаданные функции

У каждой функции есть служебные атрибуты: `__name__` (имя) и `__doc__`
(docstring). Без дополнительных мер обёрнутая функция их теряет:

```python
@my_decorator
def greet():
    """Печатает приветствие."""
    ...

greet.__name__  # 'wrapper', а не 'greet'
greet.__doc__   # None, а не 'Печатает приветствие.'
```

Это происходит потому, что `greet` теперь буквально ссылается на объект
`wrapper`, у которого свои `__name__`/`__doc__`/сигнатура. Это ломает
справку (`help(greet)`), имена в сообщениях об ошибках и инструменты,
которые читают сигнатуру функции (например, `inspect.signature`).

## `functools.wraps`

`functools.wraps` из стандартного модуля `functools` — сам по себе
декоратор (декоратор для написания декораторов), который копирует
`__name__`, `__doc__`, `__module__`, `__wrapped__` и другие метаданные с
оригинальной функции на обёртку:

```python
from functools import wraps

def my_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```

Теперь `greet.__name__ == 'greet'`, а `greet.__wrapped__` указывает на
исходную функцию.

**Правило:** любой нетривиальный декоратор должен использовать
`functools.wraps` — это дешёвая операция, которая избавляет от
труднообъяснимых багов в логировании, тестах и документации.

## Порядок применения декораторов (стекирование)

```python
@dec_a
@dec_b
def func():
    ...
```

эквивалентно `func = dec_a(dec_b(func))`.

Значит:

* **применяются** декораторы снизу вверх (`dec_b` оборачивает `func`
  первым, `dec_a` — уже результат `dec_b`);
* **выполняются** (при вызове `func()`) — сверху вниз: сначала код обёртки
  `dec_a`, которая внутри себя вызывает обёртку `dec_b`, которая вызывает
  исходную `func`.

Наглядно это как матрёшка: `dec_a` — самый внешний слой, `dec_b` —
следующий, оригинальная функция — в центре.
