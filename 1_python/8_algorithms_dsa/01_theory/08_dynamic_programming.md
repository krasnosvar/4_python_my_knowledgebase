# Динамическое программирование

Основы рекурсии (базовый случай, переход, стек вызовов, лимит глубины)
разобраны в [05_recursion_basics.md](./05_recursion_basics.md). Здесь — что
делать, когда наивная рекурсия становится слишком медленной.

**Динамическое программирование (DP)** — приём, при котором большая
задача разбивается на подзадачи, и результат каждой подзадачи
вычисляется **один раз** и запоминается, вместо того чтобы
пересчитываться снова и снова.

## Наивная рекурсия и экспоненциальный взрыв

```python
def fib_naive(n: int) -> int:
    if n < 2:
        return n
    return fib_naive(n - 1) + fib_naive(n - 2)   # O(2ⁿ) — пересчитывает одно и то же множество раз
```

`fib_naive(5)` вызывает `fib_naive(3)` дважды, `fib_naive(2)` трижды и
так далее — количество вызовов растёт экспоненциально, хотя различных
подзадач всего `n`.

## Мемоизация: рекурсия + кэш

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib_memo(n: int) -> int:
    if n < 2:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)   # O(n) — каждая подзадача считается один раз
```

Мемоизация — "динамическое программирование сверху вниз" (top-down):
та же рекурсивная структура, но каждый уникальный аргумент вычисляется
единожды, результат кэшируется.

## Динамическое программирование снизу вверх (табуляция)

Та же задача, но без рекурсии: заполняем таблицу результатов от базовых
случаев к искомому, избегая накладных расходов на вызовы функций и риска
`RecursionError`:

```python
def fib_tabulation(n: int) -> int:
    if n < 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
```

Часто можно снизить память с O(n) до O(1), храня только последние
несколько значений вместо всей таблицы:

```python
def fib_optimized(n: int) -> int:
    if n < 2:
        return n
    prev, curr = 0, 1
    for _ in range(n - 1):
        prev, curr = curr, prev + curr
    return curr
```

## Как распознать задачу на DP

Два признака:

1. **Оптимальная подструктура** — решение задачи можно построить из
   решений подзадач меньшего размера (как `fib(n)` строится из `fib(n-1)`
   и `fib(n-2)`).
2. **Перекрывающиеся подзадачи** — одни и те же подзадачи встречаются
   многократно при наивной рекурсии (в отличие, например, от merge sort,
   где подзадачи не пересекаются — там DP не даёт выигрыша).

## Пример: разменная задача (coin change)

Минимальное число монет, чтобы набрать сумму `amount`:

```python
def coin_change(coins: list[int], amount: int) -> int:
    INF = float("inf")
    dp = [0] + [INF] * amount   # dp[i] — минимум монет для суммы i
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

`dp[i]` зависит только от уже вычисленных `dp[i - coin]` для меньших
сумм — классическая табуляция снизу вверх, O(amount * len(coins)) времени.

## Практическое правило

- Если наивное решение — рекурсия с явным экспоненциальным ветвлением и
  видно, что одни и те же аргументы повторяются — добавьте `lru_cache`
  как первый шаг (минимальные изменения кода).
- Если нужна предсказуемая память/нет риска `RecursionError` на больших
  входах — перепишите в табуляцию (итеративный DP с массивом).
- Не каждая рекурсия — DP: если подзадачи не пересекаются (сортировка
  слиянием, бинарный поиск, обход дерева без повторных посещений) —
  мемоизация не даст выигрыша, там рекурсия используется просто как
  естественный способ выразить divide-and-conquer.
