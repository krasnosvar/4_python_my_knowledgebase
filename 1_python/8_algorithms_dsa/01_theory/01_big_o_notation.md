# O-нотация: оценка трудоёмкости алгоритма

Развитие алгоритмического мышления начинается с умения оценивать, как
время работы и память алгоритма растут с размером входных данных `n` —
без привязки к конкретному железу или языку.

## Что такое O-нотация

O-нотация описывает **верхнюю границу роста** функции трудоёмкости при
`n → ∞`, игнорируя константы и младшие слагаемые:

```
f(n) = 3n² + 100n + 500  →  O(n²)
```

При больших `n` слагаемое `n²` доминирует — константы `3`, `100`, `500` не
меняют характер роста, поэтому их отбрасывают. Это удобно для сравнения
алгоритмов на больших входах, но означает, что O-нотация ничего не
говорит о поведении на маленьких `n` (алгоритм с O(n²), но маленькой
константой может быть быстрее O(n log n)-алгоритма с большой константой
на входах в сотни элементов).

## Основные классы сложности (от лучшего к худшему)

| Нотация | Название | Пример |
|---|---|---|
| O(1) | константная | доступ по индексу в списке, `dict[key]` |
| O(log n) | логарифмическая | бинарный поиск |
| O(n) | линейная | обход списка один раз |
| O(n log n) | линейно-логарифмическая | эффективная сортировка (`sorted`, merge sort) |
| O(n²) | квадратичная | вложенные циклы по одному и тому же входу |
| O(2ⁿ) | экспоненциальная | наивная рекурсия без мемоизации (Фибоначчи) |
| O(n!) | факториальная | перебор всех перестановок |

## Как оценивать сложность кода

Считайте количество "элементарных" операций как функцию от `n`:

```python
def find_max(items: list[int]) -> int:      # O(n)
    best = items[0]
    for x in items:                           # цикл по n элементам
        if x > best:
            best = x
    return best

def has_duplicate_pair(items: list[int]) -> bool:  # O(n²)
    for i in range(len(items)):
        for j in range(i + 1, len(items)):      # вложенный цикл — n * n
            if items[i] == items[j]:
                return True
    return False

def has_duplicate_fast(items: list[int]) -> bool:  # O(n)
    seen = set()
    for x in items:                              # один проход
        if x in seen:                             # O(1) в среднем для set
            return True
        seen.add(x)
    return False
```

Правило: **последовательные** циклы складываются (`O(n) + O(n) = O(n)`),
**вложенные** циклы перемножаются (`O(n) * O(n) = O(n²)`).

## Сложность операций встроенных структур Python

Знание "стоимости" стандартных операций — основа оценки алгоритмов на
практике:

| Структура | Операция | Сложность |
|---|---|---|
| `list` | доступ по индексу `l[i]` | O(1) |
| `list` | `append` (в конец) | O(1) амортизированно |
| `list` | `insert(0, x)` / `pop(0)` | O(n) — сдвиг всех элементов |
| `list` | `x in l` | O(n) |
| `dict` / `set` | доступ/вставка/поиск | O(1) в среднем, O(n) в худшем случае (коллизии хешей) |
| `deque` | `append`/`appendleft`/`pop`/`popleft` | O(1) |
| `sorted(l)` | сортировка | O(n log n) |

Частая ошибка: использовать `x in list_of_million_items` в цикле (O(n) на
каждую проверку → O(n²) суммарно), когда `set`/`dict` дают ту же проверку
за O(1) в среднем.

## Пространственная сложность

O-нотация применяется и к памяти: сколько **дополнительной** памяти
требует алгоритм относительно размера входа (не считая сам вход).

```python
def reverse_in_place(items: list) -> None:   # O(1) дополнительной памяти
    items.reverse()

def reversed_copy(items: list) -> list:      # O(n) дополнительной памяти
    return items[::-1]
```

Часто есть компромисс время/память: например, `has_duplicate_fast` выше
тратит O(n) памяти на `set`, чтобы получить O(n) времени вместо O(n²).

## Best/average/worst case

Для многих алгоритмов сложность зависит от конкретных данных, не только
от `n`:

- Поиск в несортированном списке (`x in list`): worst case O(n) (элемента
  нет или он последний), best case O(1) (первый элемент).
- Быстрая сортировка (quicksort): average O(n log n), worst case O(n²) на
  специально подобранных/уже отсортированных данных без рандомизации pivot.

Когда говорят просто «O(n log n)» без уточнения — обычно имеют в виду
worst case или average case в зависимости от контекста; при оценке
критичных к производительности участков важно уточнять, какой случай
имеется в виду.
