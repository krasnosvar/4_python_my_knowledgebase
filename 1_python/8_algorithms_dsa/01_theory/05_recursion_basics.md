# Рекурсия: основы

**Рекурсия** — когда функция вызывает сама себя. Звучит как бесконечный
цикл, но работает, если каждый следующий вызов решает **меньшую** версию
той же задачи, и где-то есть точка, на которой вызовы прекращаются.

Зачем она нужна именно здесь: следующие темы — деревья
(`06_trees_and_hash_tables.md`) и сортировки слиянием/быстрая сортировка
(`07_sorting_and_searching.md`) — естественно записываются рекурсивно.
Дерево устроено «рекурсивно» само: каждый узел — корень меньшего
поддерева, поэтому «обработать дерево» = «обработать узел + обработать
левое поддерево + обработать правое поддерево».

## База + переход

Любая корректная рекурсивная функция имеет две части:

- **базовый случай** — входные данные настолько простые, что ответ
  известен сразу, без новых вызовов. Здесь рекурсия останавливается;
- **рекурсивный переход** — задача сводится к меньшей версии самой себя
  плюс немного работы.

```python
def factorial(n: int) -> int:
    if n <= 1:          # базовый случай: 1! = 1, дальше не идём
        return 1
    return n * factorial(n - 1)   # переход: n! = n * (n-1)!
```

## Как это выполняется: стек вызовов

Каждый вызов функции получает свою отдельную «рабочую область» (фрейм) со
своими локальными переменными. Фреймы складываются стопкой — **стеком
вызовов**: новый вызов кладётся сверху, а когда он завершается, снимается,
и выполнение продолжается в фрейме под ним.

Трассировка `factorial(3)`:

```text
factorial(3)  -> ждёт результата factorial(2), чтобы умножить на 3
  factorial(2)  -> ждёт результата factorial(1), чтобы умножить на 2
    factorial(1)  -> базовый случай, возвращает 1
  factorial(2)  -> получает 1, возвращает 2 * 1 = 2
factorial(3)  -> получает 2, возвращает 3 * 2 = 6
```

Сначала вызовы «спускаются» до базового случая, затем результаты
«поднимаются» обратно. Если базового случая нет (или переход не уменьшает
задачу), спуск никогда не закончится.

## Ещё пример: сумма списка

```python
def total(numbers: list[int]) -> int:
    if not numbers:                          # базовый случай: пустой список
        return 0
    return numbers[0] + total(numbers[1:])   # первый элемент + сумма остальных
```

`numbers[1:]` — срез: копия списка без первого элемента, то есть задача
стала на один элемент меньше. (Для реальной суммы, конечно, есть `sum()`
и обычный цикл — пример нужен только чтобы увидеть шаблон «база +
переход» на списке.)

## Ограничение глубины рекурсии в Python

CPython не оптимизирует хвостовую рекурсию (в отличие от некоторых
функциональных языков) — каждый рекурсивный вызов добавляет фрейм в стек
вызовов. Лимит по умолчанию — 1000 (`sys.getrecursionlimit()`), превышение
даёт исключение `RecursionError`.

```python
import sys
sys.getrecursionlimit()          # обычно 1000
sys.setrecursionlimit(5000)      # можно увеличить, но это не решает проблему
                                 # для действительно глубокой рекурсии —
                                 # риск переполнения реального стека процесса
```

Для задач с потенциально большой глубиной (обход длинного связного
списка, глубокий обход дерева) на практике часто переписывают рекурсию в
итеративную версию с явным стеком (`list` как стек из
`04_stacks_and_queues.md`), а не полагаются на увеличение лимита.

## Рекурсия против цикла

- Рекурсия удобна, когда сама структура данных рекурсивна (деревья,
  вложенные списки, «разделяй и властвуй» в сортировках) — код получается
  короче и ближе к определению задачи.
- Цикл обычно быстрее (нет накладных расходов на вызов функции) и не
  упирается в лимит глубины. Для линейных задач (сумма, факториал) в
  реальном коде выбирают цикл.
- Наивная рекурсия может пересчитывать одно и то же много раз — как это
  распознать и исправить мемоизацией, разбирается в
  `08_dynamic_programming.md`.

## Проверить понимание

Что вернёт вызов и сколько раз будет вызвана функция?

```python
def count_down(n: int) -> int:
    if n == 0:
        return 0
    return 1 + count_down(n - 1)

count_down(3)
```

<details>
<summary>Разбор</summary>

Вернёт `3`. Функция будет вызвана 4 раза: `count_down(3)`, `(2)`, `(1)` и
`(0)`. Последний вызов — базовый случай, возвращает `0`; каждый вызов выше
прибавляет `1` к результату нижнего: `0 → 1 → 2 → 3`.

</details>
