# Изменяемость и идентичность объектов

Любое значение в Python — **объект**: отдельная «вещь» в памяти. У каждого
объекта есть три свойства:

- **идентичность** (identity) — «какой именно это объект», его уникальный
  номер в памяти; узнать можно функцией `id(x)`;
- **тип** — `int`, `list`, `str`... (`type(x)`);
- **значение** — то, что внутри: `3`, `[1, 2]`, `"hi"`.

Идентичность и тип объекта не меняются никогда. А вот значение у одних
типов менять можно, у других — нет.

## Изменяемые и неизменяемые типы

- **Неизменяемые (immutable)**: `int`, `float`, `bool`, `str`, `tuple`,
  `frozenset`, `bytes`, `None`. Изменить такой объект нельзя — любая
  «модификация» на самом деле создаёт **новый** объект.
- **Изменяемые (mutable)**: `list`, `dict`, `set` (и объекты твоих
  собственных классов — см. `4_oop`). Их содержимое меняется «на месте»,
  объект остаётся тем же.

```python
s = "hello"
s += " world"   # создана НОВАЯ строка; старая, если на неё больше никто
                # не ссылается, будет удалена сборщиком мусора (GC) —
                # механизмом Python, который сам освобождает ненужную память

lst = [1, 2, 3]
lst.append(4)   # изменён ТОТ ЖЕ список, id(lst) не поменялся
```

## `is` против `==`

- `==` сравнивает **значения**: «одинаковое ли содержимое».
- `is` сравнивает **идентичность**: «это один и тот же объект в памяти»
  (то же, что `id(a) == id(b)`).

```python
a = [1, 2, 3]
b = [1, 2, 3]
a == b   # True  — содержимое одинаковое
a is b   # False — это два разных объекта
a is a   # True
```

Как именно `==` сравнивает объекты, решает их тип: у каждого типа есть
специальный метод `__eq__` («equal»), который Python вызывает при `==`.
Для своих классов его можно написать самому — это разбирается в `4_oop`.

**Идиома `x is None`** (а не `x == None`): объект `None` во всей программе
ровно один, поэтому проверка «это он и есть?» — точная и быстрая. А `==`
можно переопределить через `__eq__`, и чужой объект теоретически может
ответить `True` на `== None`.

## Кэширование мелких объектов в CPython

CPython (стандартная реализация Python) для экономии заранее создаёт
некоторые неизменяемые объекты и переиспользует их:

- **целые числа от -5 до 256** — существуют в одном экземпляре;
- **короткие строки**, похожие на имена переменных, могут
  переиспользоваться.

```python
a = 100
b = 100
a is b   # True — оба имени указывают на один заранее созданный объект

x = 1000
y = 1000
x is y   # обычно False — вне диапазона кэша это два разных объекта
```

> ⚠️ Это деталь реализации CPython, а не правило языка. **Никогда не
> сравнивайте числа или строки через `is`** — только `==`. `is` нужен для
> проверки «тот же ли это объект», например `is None`.

## Общие ссылки (aliasing) и ловушки изменяемости

Переменная в Python — это **имя**, привязанное к объекту, а не «коробка» с
данными. Присваивание не копирует объект — оно даёт ему ещё одно имя:

```python
original = [1, 2, 3]
alias = original       # alias — ещё одно имя для ТОГО ЖЕ списка
alias.append(4)
print(original)        # [1, 2, 3, 4] — изменение видно через оба имени!
```

Чтобы получить независимую копию, копируйте явно:

- `list(original)` или `original[:]` — новый список с теми же элементами;
- если внутри есть вложенные списки/словари, такая копия их **не**
  копирует (внутренние объекты останутся общими). Для полной копии
  «всего дерева» есть функция `deepcopy` из модуля `copy`:

```python
import copy
nested = [[1, 2], [3, 4]]
full_copy = copy.deepcopy(nested)   # копирует и вложенные списки
```

## Классическая ловушка: изменяемое значение по умолчанию

Это та самая ловушка, о которой предупреждал
[05_functions_basics](../../1_python_fundamentals/05_functions_basics/01_theory/01_functions_basics.md).
Значение параметра по умолчанию создаётся **один раз** — когда Python
читает `def`, а не при каждом вызове. Если это изменяемый объект, все
вызовы делят его между собой:

```python
def add_item(item, bucket=[]):   # список создаётся ОДИН раз
    bucket.append(item)
    return bucket

add_item("a")   # ['a']
add_item("b")   # ['a', 'b']  — тот же список, а не новый!
```

Правильно — использовать `None` как метку «не передали» и создавать новый
список внутри функции:

```python
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

## Почему неизменяемость упрощает жизнь

- Неизменяемый объект нельзя случайно испортить через чужое имя — его
  можно свободно передавать в функции (и между потоками — см.
  `6_concurrency`).
- Неизменяемые объекты можно использовать как ключи словаря и элементы
  множества — подробно в
  [04_hashability_and_performance.md](./04_hashability_and_performance.md).
- Функции, которые не меняют входные данные, проще тестировать: нет
  скрытых побочных эффектов.
