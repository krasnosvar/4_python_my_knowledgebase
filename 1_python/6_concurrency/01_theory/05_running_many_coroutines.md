# Конкурентный запуск корутин: gather, as_completed, TaskGroup

Есть несколько способов запустить много корутин одновременно и дождаться
результатов — они по-разному ведут себя при ошибках и отмене.

## asyncio.gather

```python
results = await asyncio.gather(
    fetch("a"), fetch("b"), fetch("c"),
)
# results — список в ТОМ ЖЕ порядке, что и аргументы, независимо от того,
# какая корутина завершилась раньше
```

- Ждёт **все** корутины, возвращает список результатов в порядке аргументов.
- По умолчанию (`return_exceptions=False`): если одна из корутин бросает
  исключение, `gather` немедленно поднимает его — но **остальные корутины
  не отменяются автоматически**, они продолжают работать в фоне (это частый
  источник багов — «зависшие» задачи после первого исключения).
- `return_exceptions=True` — исключения возвращаются в списке результатов
  как объекты, `gather` не бросает исключение сам, ошибки нужно проверять
  вручную.

```python
results = await asyncio.gather(*coros, return_exceptions=True)
for r in results:
    if isinstance(r, Exception):
        handle(r)
```

## asyncio.as_completed

Возвращает результаты **по мере готовности**, а не в порядке аргументов —
удобно для прогресс-баров или обработки первого пришедшего результата:

```python
for coro in asyncio.as_completed([fetch("a"), fetch("b"), fetch("c")]):
    result = await coro   # первым придёт тот, кто закончился раньше
    print(result)
```

Порядок результатов не гарантирован и не совпадает с порядком исходного
списка. При исключении в одной из корутин — оно всплывает в момент
`await coro` для конкретного элемента, остальные продолжают работать.

## asyncio.TaskGroup (Python 3.11+)

Структурная конкурентность: группа задач с чёткими границами области видимости
и согласованной семантикой отмены при ошибке.

```python
async def main():
    async with asyncio.TaskGroup() as tg:
        tg.create_task(fetch("a"))
        tg.create_task(fetch("b"))
        tg.create_task(fetch("c"))
    # сюда управление придёт только когда ВСЕ задачи завершились
```

Ключевые отличия от `gather`:

- Если любая задача в группе бросает исключение — **все остальные задачи
  группы автоматически отменяются**, а не продолжают работать в фоне.
- Если упало несколько задач одновременно — они собираются в
  `ExceptionGroup` (PEP 654), а не теряются («видна только первая ошибка»,
  как в `gather`).
- Обработка через `except*`:

```python
try:
    async with asyncio.TaskGroup() as tg:
        tg.create_task(fetch("a"))
        tg.create_task(fetch("b"))
except* ValueError as eg:
    for e in eg.exceptions:
        print("value error:", e)
except* ConnectionError as eg:
    for e in eg.exceptions:
        print("connection error:", e)
```

`TaskGroup` — рекомендуемый способ запускать несколько задач конкурентно
в новом коде на 3.11+: он не оставляет «сироток» после ошибки и явно
показывает границы жизни задач.

## Сравнительная таблица

| Способ | Порядок результатов | Поведение при ошибке | Версия |
|---|---|---|---|
| `gather()` | как в аргументах | бросает первую ошибку, остальные корутины не отменяются | любая |
| `gather(return_exceptions=True)` | как в аргументах | ошибки — как значения в списке | любая |
| `as_completed()` | по готовности | ошибка всплывает при обработке конкретного элемента | любая |
| `TaskGroup` | нет единого списка (нужно собирать вручную) | все задачи группы отменяются, ошибки — в `ExceptionGroup` | 3.11+ |

## Практический совет

- Нужен простой «запустить N штук и получить N результатов по порядку» —
  `gather`.
- Нужно реагировать на первый готовый результат — `as_completed`.
- Пишете новый код на 3.11+, важна корректная отмена при ошибках —
  `TaskGroup`.
- `TaskGroup` также хорош, когда задачи держат внешние ресурсы (сокеты,
  файлы) — гарантированная отмена при ошибке одной из них снижает риск
  утечек.
