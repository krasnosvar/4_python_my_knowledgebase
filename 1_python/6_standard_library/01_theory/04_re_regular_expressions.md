# re: регулярные выражения на практическом уровне

**Регулярное выражение (regex)** — маленький язык шаблонов для поиска
текста: вместо «найди строку `42`» можно сказать «найди одну или больше
цифр подряд» (`\d+`). Пригождается для разбора логов, валидации
форматов, вытаскивания кусков из строк.

## Шпаргалка по синтаксису

| Шаблон | Что совпадает | Пример |
|---|---|---|
| `abc` | ровно эти символы | `cat` находит `cat` в `concatenate` |
| `.` | любой один символ (кроме перевода строки) | `c.t` → `cat`, `cut` |
| `\d` | одна цифра `0-9` | `\d\d` → `42` |
| `\w` | буква, цифра или `_` | `\w` → `a`, `Z`, `7`, `_` |
| `\s` | пробельный символ (пробел, таб, перевод строки) | `a\sb` → `a b` |
| `[abc]` | один символ из набора | `[aeiou]` → гласная |
| `[a-z]` | один символ из диапазона | `[0-9a-f]` → шестнадцатеричная цифра |
| `[^abc]` | один символ **не** из набора | `[^0-9]` → не цифра |
| `*` | предыдущее 0 или более раз | `ab*` → `a`, `ab`, `abbb` |
| `+` | предыдущее 1 или более раз | `\d+` → `7`, `2026` |
| `?` | предыдущее 0 или 1 раз (необязательно) | `colou?r` → `color`, `colour` |
| `{n,m}` | предыдущее от n до m раз | `\d{2,4}` → `42`, `2026` |
| `^` / `$` | начало / конец строки | `^\d+$` → строка только из цифр |
| `(...)` | группа: объединяет часть шаблона и «запоминает» совпадение | `(\d+)-(\d+)` |
| `a\|b` | `a` или `b` | `cat\|dog` |
| `\.` | экранирование: буквально точка (а не «любой символ») | `\d+\.\d+` → `3.14` |

**Почему строки шаблонов пишут как `r"..."`.** Префикс `r` делает строку
«сырой» (raw): обратный слеш `\` в ней остаётся обычным символом. Без `r`
Python сам попытался бы интерпретировать `\d` или `\b` как
escape-последовательность строки (`"\b"` — это символ backspace!), и
шаблон сломался бы. Правило: шаблоны для `re` всегда пишите с `r`.

## Базовые функции

```python
import re

re.search(r"\d+", "order-42")     # первое совпадение где угодно в строке -> Match или None
re.match(r"\d+", "42-order")      # совпадение только с НАЧАЛА строки
re.fullmatch(r"\d+", "42")        # вся строка целиком должна совпасть
re.findall(r"\d+", "a1 b22 c333") # ['1', '22', '333'] — все непересекающиеся совпадения
re.finditer(r"\d+", "a1 b22")     # то же, но ленивый итератор Match-объектов (позиции, группы)
re.sub(r"\d+", "#", "a1 b22")     # 'a# b#' — замена всех совпадений
re.split(r"\s*,\s*", "a, b,c")    # ['a', 'b', 'c'] — разбиение по паттерну-разделителю
```

`re.match` — частый источник путаницы: многие ожидают поведения `search`,
но `match` проверяет совпадение только с начала строки (не требует, чтобы
совпадение покрывало **всю** строку — для этого `fullmatch`).

## Компиляция паттерна

```python
pattern = re.compile(r"(?P<user>\w+)@(?P<domain>[\w.]+)")

m = pattern.search("contact: den@example.com")
if m:
    print(m.group("user"), m.group("domain"))  # den example.com
    print(m.groupdict())                        # {'user': 'den', 'domain': 'example.com'}
```

Именованные группы (`(?P<name>...)`) читаемее позиционных (`m.group(1)`) —
особенно когда групп больше двух-трёх. `re.compile` имеет смысл, когда один
и тот же паттерн используется многократно в цикле — компиляция один раз,
затем переиспользование скомпилированного объекта (сам модуль `re` кэширует
последние скомпилированные паттерны, но явная компиляция яснее показывает
намерение и не зависит от размера внутреннего кэша).

## Жадные и нежадные квантификаторы

```python
re.findall(r"<.+>", "<a><b>")   # ['<a><b>'] — жадный: захватывает максимум
re.findall(r"<.+?>", "<a><b>") # ['<a>', '<b>'] — нежадный (lazy): минимально возможное
```

Для парсинга «тегоподобных» структур почти всегда нужен нежадный `+?`/`*?`,
иначе жадный квантификатор захватит от первого `<` до последнего `>`.

## Частые практические паттерны

```python
EMAIL = re.compile(r"^[\w.+-]+@[\w-]+\.[a-zA-Z]{2,}$")
PHONE = re.compile(r"^\+?\d{10,15}$")
UUID  = re.compile(r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$", re.IGNORECASE)

def extract_log_level(line: str) -> str | None:
    m = re.search(r"\b(DEBUG|INFO|WARNING|ERROR|CRITICAL)\b", line)
    return m.group(1) if m else None
```

## Флаги

```python
re.search(r"^hello", "Hello\nworld", re.IGNORECASE | re.MULTILINE)
```

- `re.IGNORECASE` (`re.I`) — регистронезависимое сравнение.
- `re.MULTILINE` (`re.M`) — `^`/`$` совпадают с началом/концом **каждой** строки, а не только всей строки целиком.
- `re.DOTALL` (`re.S`) — `.` совпадает и с символом новой строки тоже.
- `re.VERBOSE` (`re.X`) — позволяет писать паттерн многострочно с комментариями:

```python
PATTERN = re.compile(r"""
    (?P<year>\d{4})   # год
    -
    (?P<month>\d{2})  # месяц
    -
    (?P<day>\d{2})    # день
""", re.VERBOSE)
```

## Когда НЕ использовать regex

- Разбор HTML/XML/JSON — используйте специализированные парсеры
  (`html.parser`, `xml.etree`, `json`). Regex не умеет корректно работать с
  вложенными/рекурсивными структурами.
- Простая проверка «начинается с»/«заканчивается на»/«содержит подстроку» —
  `str.startswith`/`str.endswith`/`in` быстрее и читаемее регулярного выражения.
- Валидация email по RFC целиком — RFC 5322 практически невозможно покрыть
  одним regex; для реальной валидации проще проверить базовый паттерн +
  отправить письмо с подтверждением.

## Производительность: catastrophic backtracking

Паттерны с вложенными квантификаторами над пересекающимися альтернативами
(`(a+)+b` на строке без `b` в конце) могут давать экспоненциальное время
работы движка regex. Признак: сложный паттерн со вложенными `*`/`+` внутри
групп с `*`/`+` снаружи — стоит упростить структуру или ограничить длину
входа перед матчингом.
