# functools и itertools: что не покрыто в generators/decorators

Базовые генераторы, `yield`, `map`/`filter` разобраны в
`4_iterators_generators`.
Здесь — инструменты `functools`/`itertools`, которые не про ленивые
вычисления как таковые, а про кэширование, композицию функций и готовые
рецепты для итераторов.

## functools.reduce

Свёртка последовательности к одному значению через бинарную операцию:

```python
from functools import reduce

total = reduce(lambda acc, x: acc + x, [1, 2, 3, 4], 0)  # 10
product = reduce(lambda acc, x: acc * x, [1, 2, 3, 4])   # 24, без начального значения
```

В большинстве случаев `sum()`, `math.prod()`, генераторное выражение или
явный цикл читаются лучше, чем `reduce` — используйте его, когда операция
свёртки нестандартна (например, слияние словарей, построение дерева) и
явный цикл действительно менее читаем.

## functools.partial — частичное применение

```python
from functools import partial

def power(base: float, exponent: float) -> float:
    return base ** exponent

square = partial(power, exponent=2)
cube = partial(power, exponent=3)
print(square(5), cube(5))  # 25 216
```

Удобно для передачи функции с частью аргументов туда, где ожидается
callback с фиксированной сигнатурой (`sorted(key=partial(...))`,
`executor.submit(partial(...))`, обработчики событий).

## functools.lru_cache и functools.cache

Мемоизация — кэширование результатов чистой функции по аргументам:

```python
from functools import lru_cache

@lru_cache(maxsize=128)
def fib(n: int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

- `maxsize=None` (или `@cache` в 3.9+, синоним `lru_cache(maxsize=None)`) —
  кэш без ограничения размера, растёт бесконечно. Подходит для функций с
  конечным и небольшим множеством возможных аргументов.
- `maxsize=128` (по умолчанию) — LRU-вытеснение: при превышении размера
  выкидывается наименее давно использованный результат.
- Аргументы функции должны быть **хешируемыми** (кортежи, числа, строки —
  да; списки, словари — нет).
- `fib.cache_info()` — статистика хитов/промахов; `fib.cache_clear()` —
  сброс кэша (полезно в тестах, чтобы не тащить состояние между тестами).

**Ловушка**: `lru_cache` на методе экземпляра держит ссылку на `self` в
ключе кэша — это может продлевать жизнь объектов дольше ожидаемого
(утечка памяти в долгоживущих процессах). Для методов часто предпочитают
кэшировать на уровне модуля/класса или использовать `functools.cached_property`.

## functools.cached_property

```python
from functools import cached_property

class Report:
    def __init__(self, rows: list[dict]) -> None:
        self.rows = rows

    @cached_property
    def total(self) -> float:
        print("считаю сумму...")
        return sum(r["amount"] for r in self.rows)

r = Report([{"amount": 1}, {"amount": 2}])
print(r.total)  # считаю сумму... 3
print(r.total)  # 3 — без повторного вычисления, результат сохранён в __dict__
```

В отличие от `@property` + `lru_cache`, `cached_property` вычисляет
значение один раз и кладёт его прямо в `__dict__` экземпляра под тем же
именем — при следующем обращении атрибут находится напрямую, минуя дескриптор.
Значит: класс не должен использовать `__slots__` (нужен `__dict__`), а
значение считается «правильным» на весь срок жизни объекта (нет
инвалидации кэша при изменении исходных данных).

Пояснения к терминам абзаца выше:

- **`__dict__`** — обычный словарь, в котором объект хранит свои атрибуты
  (`obj.x = 1` по сути пишет `obj.__dict__["x"] = 1`).
- **`__slots__`** — объявление в классе фиксированного списка атрибутов
  (`__slots__ = ("x", "y")`): объекты такого класса не получают
  `__dict__`, зато занимают меньше памяти. Обратная сторона — добавить
  атрибут вне списка нельзя, и `cached_property` работать не сможет.
- **Дескриптор** — объект, который «перехватывает» чтение/запись атрибута
  класса (так устроены `@property` и сам `cached_property`). Для
  использования этих декораторов знать механику дескрипторов не нужно.

## itertools: то, что не входит в базовый набор ленивых вычислений

```python
import itertools

list(itertools.chain([1, 2], [3, 4]))          # [1, 2, 3, 4] — склейка без копирования
list(itertools.groupby("aaabbbcca"))            # группы подряд идущих одинаковых элементов
list(itertools.product([1, 2], ["a", "b"]))     # декартово произведение: (1,'a') (1,'b') (2,'a') (2,'b')
list(itertools.combinations([1, 2, 3], 2))      # [(1,2), (1,3), (2,3)] — без повторов, без учёта порядка
list(itertools.permutations([1, 2, 3], 2))      # все упорядоченные пары
list(itertools.islice(itertools.count(10), 5))  # [10, 11, 12, 13, 14] — срез бесконечного итератора
```

- `groupby` группирует только **подряд идущие** одинаковые элементы — почти
  всегда нужно сначала отсортировать вход по тому же ключу, иначе группы
  «развалятся» на несколько.
- `chain` не создаёт новый список — итерирует по вложенным итерируемым
  последовательно, без копирования в память.
- `islice` — единственный безопасный способ «срезать» бесконечный итератор
  (`itertools.count()`, `itertools.cycle()`) без ухода в бесконечный цикл.

## Практическое правило

- Нужна свёртка стандартной операции (`+`, `*`, `max`) — `sum`/`math.prod`/`max`,
  не `reduce`.
- Нужна нестандартная свёртка — `reduce` с явной lambda/функцией.
- Нужно кэшировать чистую функцию по аргументам — `lru_cache`/`cache`.
- Нужно кэшировать вычисляемый атрибут объекта один раз — `cached_property`.
- Нужны комбинаторные рецепты (группировки, комбинации, декартово произведение)
  — `itertools`, а не ручные вложенные циклы.
