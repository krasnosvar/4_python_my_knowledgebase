# Классы и магические методы

Как объявить класс, что такое объект, атрибут, метод и `self` — разобрано
в [01_what_is_a_class.md](./01_what_is_a_class.md). Здесь — следующий шаг:
как сделать так, чтобы ваши объекты работали со встроенными возможностями
языка.

Магические методы (dunder-методы, от «double underscore» — двойное
подчёркивание) — это то, как Python подключает встроенное поведение (`+`,
`len()`, `[]`, `print()`, сравнение `==`) к вашим классам. Это не
«синтаксический сахар для красоты»: интерпретатор сам вызывает их в
конкретных ситуациях. `__init__` из предыдущего файла — тоже магический
метод.

## `__init__` vs `__new__`

* `__new__(cls, ...)` — создаёт объект (выделяет под него память) и
  возвращает его. Вызывается первым. `cls` — сам класс (а не объект).
* `__init__(self, ...)` — заполняет уже созданный объект данными. Ничего не
  возвращает (точнее, обязан вернуть `None`).

На практике `__new__` переопределяют редко: неизменяемые типы (наследники
`int`, `str`, `tuple`), синглтоны (класс, у которого может быть только один
объект), метаклассы. В прикладном коде почти всегда достаточно `__init__`.

```python
class Point:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y
```

## `__repr__` против `__str__`

* `__repr__` — однозначное, «для разработчика» представление. Идеал:
  строка, по которой можно воссоздать объект (`Point(x=1, y=2)`), либо
  хотя бы `<Point x=1 y=2>`.
* `__str__` — читаемое, «для пользователя» представление (его использует
  `print()` и `str(obj)`).

Если `__str__` не определён, Python **использует `__repr__`**. Поэтому
`__repr__` стоит определять почти всегда, а `__str__` — только когда
пользовательское представление действительно должно отличаться от
отладочного. Без своего `__repr__` объект печатается как
`<__main__.Point object at 0x7f...>` — бесполезно при отладке.

```python
class Point:
    def __repr__(self) -> str:
        return f"Point(x={self.x!r}, y={self.y!r})"
```

`!r` внутри f-строки значит «подставить `repr()` значения, а не `str()`»:
для строки это добавит кавычки, и `Point(x='1')` не спутать с
`Point(x=1)`.

`repr()` вызывается неявно везде, где Python показывает объект «сам по
себе»: в интерактивной консоли, внутри `list`/`dict` при их печати, в
сообщениях об ошибках.

## `__eq__` и хешируемость

По умолчанию два объекта равны (`==`), только если это один и тот же
объект (`is`), а хеш считается по его `id()`. Как только вы определяете
`__eq__`, Python **автоматически убирает унаследованный `__hash__`**,
выставляя его в `None` — объект становится нехешируемым (нельзя
использовать как ключ словаря или элемент множества; что такое хеш — см.
[2_basics/04_hashability_and_performance.md](../../2_basics/01_theory/04_hashability_and_performance.md)).

`isinstance(obj, Класс)` в примере ниже — встроенная функция, которая
проверяет, является ли `obj` экземпляром класса `Класс`:

```python
class Point:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def __eq__(self, other: object) -> bool:
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)

p = Point(1, 2)
p == Point(1, 2)   # True — сравнение по значению
# hash(p)          # TypeError: unhashable type: 'Point'
```

Причина этого правила — требование хеш-таблиц: если `a == b`, то обязано
быть `hash(a) == hash(b)`. Python не может гарантировать это
автоматически для вашего `__eq__`, поэтому просто отключает хеш, пока вы
явно не определите `__hash__` сами (или не используете
`@dataclass(frozen=True)`, который сделает это за вас — см.
[05_dataclasses.md](./05_dataclasses.md)).

Правило: если объект логически неизменяем и вы хотите класть его в
`set`/`dict`, определяйте `__hash__` согласованно с `__eq__` (обычно как
`hash()` от того же кортежа полей, что участвует в сравнении).

## `__len__`, `__getitem__`, `__setitem__`

Эти методы превращают объект в «контейнероподобный»:

* `__len__` — включает `len(obj)` и делает объект truthy/falsy-совместимым
  (пустой контейнер — `False` в `if`, если `__bool__` не определён
  отдельно).
* `__getitem__(self, key)` — включает `obj[key]`, а также **автоматически
  даёт возможность перебора в `for`** через последовательные
  `obj[0], obj[1], ...` до ошибки `IndexError`, если `__iter__` не
  определён явно.
* `__setitem__(self, key, value)` — включает `obj[key] = value`.

```python
class Row:
    def __init__(self, values: list[int]) -> None:
        self._values = values

    def __len__(self) -> int:
        return len(self._values)

    def __getitem__(self, index: int) -> int:
        return self._values[index]
```

Это тот механизм, благодаря которому `for x in row` работает даже без
явного итератора — подробнее в разделе
[5_iterators_generators](../../5_iterators_generators/README.md).
(Подчёркивание в `_values` — соглашение «внутренний атрибут, не трогайте
снаружи», подробно — в [06_property_and_encapsulation.md](./06_property_and_encapsulation.md).)

## Перегрузка операторов

`__add__`, `__sub__`, `__mul__`, `__lt__`, `__contains__` и другие
dunder-методы позволяют задать поведение операторов (`+`, `-`, `*`, `<`,
`in`) для собственных типов:

```python
class Vector:
    def __init__(self, x: float, y: float) -> None:
        self.x, self.y = x, y

    def __add__(self, other: "Vector") -> "Vector":
        return Vector(self.x + other.x, self.y + other.y)

Vector(1, 2) + Vector(3, 4)   # Python вызовет Vector(1, 2).__add__(Vector(3, 4))
```

Общее правило: перегружайте оператор только если он сохраняет
интуитивный смысл из математики/встроенных типов. `__add__`, который
втихую изменяет один из операндов или делает тяжёлый побочный эффект, —
источник трудноуловимых багов.
