# `@property` и инкапсуляция

## В Python нет настоящей приватности

В отличие от Go (регистр буквы) или Java (`private`/`protected`/`public`), в Python любой атрибут технически доступен снаружи. Есть только соглашения:

* `_attr` (одно подчёркивание) — «внутреннее использование», не является частью публичного API. Интерпретатор никак это не проверяет — это просто сигнал для других разработчиков.
* `__attr` (два подчёркивания в начале, без двух в конце) — включает **name mangling**: Python переименовывает атрибут в `_ClassName__attr` на уровне байткода.

```python
class Account:
    def __init__(self, balance: float) -> None:
        self.__balance = balance

a = Account(100)
# a.__balance          # AttributeError
a._Account__balance      # 100 — доступ всё равно есть, просто нужно знать mangled-имя
```

Name mangling существует не для «защиты данных», а чтобы избежать **конфликта имён при наследовании** — если подкласс случайно определит атрибут с тем же именем, что и приватный атрибут родителя, mangling предотвратит их взаимное затирание. Это не механизм безопасности.

## `@property` — управляемый доступ к атрибуту

`@property` позволяет обращаться к методу как к обычному атрибуту (без скобок), сохраняя возможность добавить логику при чтении, записи или удалении:

```python
class Circle:
    def __init__(self, radius: float) -> None:
        self._radius = radius

    @property
    def radius(self) -> float:
        return self._radius

    @radius.setter
    def radius(self, value: float) -> None:
        if value <= 0:
            raise ValueError("радиус должен быть положительным")
        self._radius = value

    @property
    def area(self) -> float:
        return 3.14159 * self._radius ** 2  # вычисляемый атрибут, только для чтения
```

```python
c = Circle(5)
c.radius = 10        # проходит через setter и валидацию
print(c.area)         # вычисляется на лету, нет собственного setter — нельзя присвоить
```

`@x.deleter` аналогично перехватывает `del obj.x`.

## Когда использовать `property`, а когда — обычный атрибут

* **Обычный публичный атрибут** — если это просто данные без инвариантов (`self.name = name`). Оборачивать в property «на всякий случай» — избыточно и не идиоматично для Python (в отличие от Java, где геттеры/сеттеры — привычка по умолчанию).
* **`@property`** нужен, когда:
  * значение требует валидации при установке;
  * значение вычисляется из других полей (не должно храниться отдельно и рассинхронизироваться);
  * нужно сохранить обратную совместимость API: было публичное поле `obj.x`, стало вычисляемым — заменить `self.x = ...` на `@property` можно **без изменения кода, использующего класс**, потому что синтаксис доступа (`obj.x`) не меняется.

Последний пункт — практическая причина, почему в Python принято начинать с простых публичных атрибутов и вводить `@property` только тогда, когда появляется реальная необходимость, а не заранее «для инкапсуляции».
