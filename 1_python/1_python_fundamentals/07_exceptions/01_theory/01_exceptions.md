# Исключения

До сих пор мы считали, что код всегда выполняется успешно. Но
пользователь может ввести «abc» там, где ждали число, а делитель может
оказаться нулём. В таких ситуациях Python не может продолжить работу и
**выбрасывает исключение** (exception) — специальный сигнал «что-то пошло
не так». Если исключение никто не обработал, программа останавливается и
печатает отчёт об ошибке.

## Что такое traceback и как его читать

```python
def to_number(text):
    return int(text)

to_number("abc")
```

Запуск этого кода остановится с таким сообщением:

```text
Traceback (most recent call last):
  File "demo.py", line 4, in <module>
    to_number("abc")
  File "demo.py", line 2, in to_number
    return int(text)
ValueError: invalid literal for int() with base 10: 'abc'
```

Это **traceback** — «след» вызовов, который привёл к ошибке. Читать его
удобнее **снизу вверх**:

1. Последняя строка — самое важное: **тип исключения** (`ValueError`) и
   **сообщение** (`'abc'` нельзя превратить в целое число).
2. Выше — где именно это случилось: файл, номер строки (`line 2`), функция
   (`to_number`) и сама строка кода.
3. Ещё выше — кто вызвал эту функцию (`line 4`). Строк может быть много,
   если функции вызывают друг друга.

Привычка «сначала читаю последнюю строку traceback» экономит больше
времени, чем любой другой навык отладки.

## Частые встроенные исключения

| Исключение | Когда возникает | Пример |
|---|---|---|
| `ValueError` | тип подходящий, но значение — нет | `int("abc")` |
| `TypeError` | операция не подходит для этого типа | `"5" + 5` |
| `ZeroDivisionError` | деление на ноль | `10 / 0` |
| `NameError` | имя (переменная, функция) не объявлено | `print(user_nmae)` |
| `KeyError` | нет такого ключа в словаре | `ages["Глеб"]` (см. [тему 1.5](../../05_collections/)) |
| `IndexError` | нет элемента с таким номером в списке | `fruits[10]` (см. [тему 1.5](../../05_collections/)) |

## try / except — перехватить ошибку

Если ошибка ожидаема (пользователь вполне может ввести не число), её можно
**перехватить** и обработать, вместо того чтобы падать:

```python
text = "abc"

try:
    number = int(text)          # код, который может упасть
    print(f"Число: {number}")
except ValueError:
    print("Это не число")       # выполнится, только если в try был ValueError
```

Python выполняет блок `try`. Если там случилось исключение указанного
типа, остаток `try` пропускается и выполняется блок `except`. Если ошибки
не было — `except` не выполняется вовсе.

### Перехватывай конкретный тип, а не всё подряд

Можно написать `except:` без типа — тогда перехватится **любая** ошибка.
Это плохая идея:

```python
try:
    number = int(txet)    # опечатка в имени переменной -> NameError
except:
    print("Это не число")  # врёт: проблема не во вводе, а в коде
```

Голый `except` прячет настоящие баги (здесь — опечатку `txet`) под видом
«ожидаемой» ошибки. Всегда указывай тот тип, который действительно
ожидаешь (`except ValueError:`). Если нужно обработать несколько типов —
несколько блоков `except` подряд:

```python
try:
    result = 10 / int(text)
except ValueError:
    print("Это не число")
except ZeroDivisionError:
    print("На ноль делить нельзя")
```

### `as e` — посмотреть на саму ошибку

```python
try:
    int("abc")
except ValueError as e:
    print(f"Ошибка: {e}")   # Ошибка: invalid literal for int() with base 10: 'abc'
```

`e` — объект исключения; при печати он показывает то же сообщение, что
последняя строка traceback.

## else и finally

```python
try:
    number = int(text)
except ValueError:
    print("Это не число")
else:
    print(f"Получилось: {number}")   # только если ошибки НЕ было
finally:
    print("Проверка завершена")       # выполнится ВСЕГДА
```

- `else` — код, который нужно выполнить только при успехе `try`. Его не
  кладут внутрь `try`, чтобы случайно не перехватить ошибку из него.
- `finally` — выполняется в любом случае: была ошибка или нет. Обычно там
  освобождают ресурсы («закрыть файл», «отключиться») — это встретится в
  следующих разделах.

## Главный пример: просить ввод, пока он не станет правильным

Соберём всё вместе: `input()` всегда возвращает строку (тема 3), а `int()`
падает на нечисловой строке. Цикл `while` (тема 4) будет спрашивать снова,
пока ввод не получится превратить в число:

```python
while True:
    text = input("Сколько тебе лет? ")
    try:
        age = int(text)
    except ValueError:
        print("Нужно ввести целое число, попробуй ещё раз")
        continue              # к следующей итерации - спросить снова
    break                     # сюда попадаем, только если int() не упал

print(f"Через год тебе будет {age + 1}")
```

`while True` — «бесконечный» цикл, из которого выходят через `break`,
когда получено правильное значение.

## raise — выбросить исключение самому

Иногда значение технически подходит по типу, но не имеет смысла для
твоей программы: возраст `-5` — вполне `int`, но не возраст. Своя функция
может сама сообщить об ошибке через `raise`:

```python
def check_age(age):
    if age < 0:
        raise ValueError(f"Возраст не может быть отрицательным: {age}")
    return age
```

`raise` немедленно прерывает функцию — как `return`, но вместо значения
вызывающий код получает исключение, которое можно перехватить через
`try`/`except`.

### Повторный raise

Иногда ошибку нужно заметить (например, напечатать), но не скрывать — пусть
её обработает тот, кто вызвал функцию. Для этого внутри `except` пишут
`raise` без аргументов — оно выбросит **то же самое** исключение дальше:

```python
def parse_price(text):
    try:
        return float(text)
    except ValueError:
        print(f"Не удалось разобрать цену: {text!r}")
        raise               # пробросить ту же ошибку вызывающему коду
```

(`{text!r}` в f-строке печатает значение вместе с кавычками —
удобно, чтобы увидеть пустую строку или лишние пробелы.)

## Проверить понимание

Что напечатает этот код?

```python
try:
    result = 10 / 0
    print("A")
except ValueError:
    print("B")
except ZeroDivisionError:
    print("C")
finally:
    print("D")
```

<details>
<summary>Разбор</summary>

Напечатает `C`, затем `D`. Деление `10 / 0` выбрасывает
`ZeroDivisionError`, поэтому `print("A")` не выполнится — остаток `try`
пропускается. Блок `except ValueError` не подходит по типу, следующий
`except ZeroDivisionError` — подходит, он печатает `C`. `finally`
выполняется всегда — печатает `D`.

</details>
