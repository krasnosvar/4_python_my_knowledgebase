# Списки, кортежи, множества и словари

Коллекция — значение, которое хранит внутри несколько других значений. В
Python четыре основные встроенные коллекции: `list`, `tuple`, `set` и
`dict`. Сначала разберём их синтаксис и базовые операции, а затем — чем они
отличаются и когда какую выбирать.

## `list` — изменяемый список

Список — упорядоченный набор значений в квадратных скобках, который можно
менять после создания:

```python
fruits = ["яблоко", "груша", "слива"]   # создать список
empty = []                              # пустой список

fruits[0]       # "яблоко" — элемент по индексу, счёт с 0
fruits[-1]      # "слива"  — отрицательный индекс считает с конца
fruits[0:2]     # ["яблоко", "груша"] — срез: с 0 до 2, не включая 2
fruits[:]       # поверхностная копия всего списка

len(fruits)             # 3 — количество элементов
fruits.append("киви")   # добавить элемент в конец
fruits[1] = "манго"     # заменить элемент по индексу
"груша" in fruits       # True или False — есть ли элемент в списке

for fruit in fruits:    # перебор элементов по порядку
    print(fruit)
```

Запись `fruits.append(...)` — это вызов **метода**: функции, которая
«принадлежит» значению и вызывается через точку.

У среза можно указать третий параметр — шаг `список[старт:стоп:шаг]`:
например, `fruits[::-1]` возвращает новый список с элементами в обратном
порядке (то же работает и для строк: `"abc"[::-1]` даёт `"cba"`).

## `tuple` — неизменяемый кортеж

Кортеж устроен как список, но **изменить его после создания нельзя**.
Записывается в круглых скобках:

```python
point = (10, 20)
point[0]          # 10 — индексы и срезы работают так же, как у списка
# point[0] = 5    # ошибка TypeError: кортеж менять нельзя

x, y = point      # распаковка: x = 10, y = 20
a, b = 1, 2       # то же самое: справа неявно создаётся кортеж (1, 2)
single = (42,)    # кортеж из одного элемента требует запятую!
```

Кортеж удобен для «записи» фиксированной структуры (например, координата
`(x, y)` или пара `(host, port)`), которую никто не должен случайно
изменить по дороге.

## `set` — множество уникальных элементов

Множество хранит только **уникальные** значения и не гарантирует порядок
элементов:

```python
tags = {"python", "backend", "python"}   # дубль исчезнет автоматически
print(tags)        # {'python', 'backend'} — порядок не гарантирован
tags.add("sql")    # добавить элемент
tags.discard("go") # удалить элемент, если он есть (без ошибки, если нет)
"sql" in tags      # True — очень быстрая проверка принадлежности
empty = set()      # пустое множество (не {} — это пустой словарь!)
```

## `dict` — словарь (пары «ключ → значение»)

Словарь хранит пары `ключ: значение` и позволяет мгновенно находить
значение по ключу, а не по числовому индексу:

```python
ages = {"Анна": 30, "Борис": 25}
ages["Анна"]            # 30 — получить значение по ключу
ages["Вера"] = 41       # добавить новую пару или перезаписать старую
"Борис" in ages         # True — оператор in проверяет именно КЛЮЧИ
ages.get("Глеб")        # None — ключа нет, но без ошибки
ages.get("Глеб", 0)     # 0 — вернуть значение по умолчанию, если ключа нет
# ages["Глеб"]          # ошибка KeyError: такого ключа нет

ages.keys()             # все ключи
ages.values()           # все значения
for name, age in ages.items():   # пары (ключ, значение) + распаковка
    print(name, age)
```

С версии Python 3.7 словарь **гарантированно** сохраняет порядок, в котором
ключи были добавлены.

Если при создании словаря один и тот же ключ указан дважды, останется
**последнее** значение — предыдущее молча перезапишется:

```python
d = {"a": 1, "a": 2}
print(d)                # {'a': 2}

pairs = [("x", 1), ("x", 2), ("y", 3)]
print(dict(pairs))      # {'x': 2, 'y': 3} — dict() из списка пар
```

## Почему ключ словаря и элемент множества должны быть неизменяемыми

В `set` и ключи `dict` можно класть числа, строки, `bool`, `None` и кортежи
из них — но **нельзя** положить список, словарь или другое множество:

```python
cache = {}
cache[("GET", "/users", 1)] = "ok"   # кортеж — можно
# cache[["GET", "/users", 1]] = "ok" # ошибка TypeError: unhashable type: 'list'
```

Причина в том, как `set` и `dict` ищут элементы. Вместо перебора всех
элементов подряд они вычисляют от значения числовой «отпечаток» — **хеш**
(функция `hash(x)`), и по нему сразу находят нужное место. Если бы список
можно было положить в множество, а потом изменить через `append()`, его
хеш изменился бы, и множество больше не смогло бы найти этот элемент.

Поэтому в Python действует правило:

- **Неизменяемые типы** (`int`, `float`, `bool`, `str`, `None`, а также
  `tuple`, если все его элементы тоже неизменяемы) — **хешируемы**: их
  можно использовать как ключи `dict` и элементы `set`.
- **Изменяемые типы** (`list`, `dict`, `set`) — **нехешируемы**: попытка
  положить их в `set` или в ключ `dict` вызовет `TypeError`.

## Скорость поиска и выбор коллекции

Два коротких обозначения, которые часто встречаются при разговоре о
скорости кода (подробно они разбираются в разделе
[8_algorithms_dsa](../../../8_algorithms_dsa/01_theory/01_big_o_notation.md)):

- **O(1)** («за константное время») — время операции не зависит от размера
  коллекции: что 10 элементов, что миллион — одинаково быстро.
- **O(n)** («линейно») — время растёт пропорционально числу элементов `n`:
  в 10 раз больше элементов — примерно в 10 раз дольше.

Главное практическое отличие коллекций по скорости:

- В списке (`list`) и кортеже (`tuple`) взять элемент по индексу `lst[i]` —
  **O(1)**, но проверка `x in lst` перебирает элементы по одному с начала —
  **O(n)**. Вставка или удаление в начале списка (`lst.insert(0, x)`,
  `del lst[0]`) тоже требуют **O(n)**, так как сдвигают остальные элементы.
- В множестве (`set`) и словаре (`dict`) проверка `x in s` и поиск по ключу
  `d[key]` работают через хеш — **O(1) в среднем**, независимо от размера.

Пример удаления дублей из списка с сохранением порядка первых появлений:

```python
incoming_ids = [3, 1, 3, 2, 1]
seen = set()
unique_ids = []

for event_id in incoming_ids:
    if event_id not in seen:      # быстрая проверка по множеству — O(1)
        seen.add(event_id)
        unique_ids.append(event_id)

print(unique_ids)                  # [3, 1, 2]
```

| Задача | Какую коллекцию выбрать |
|---|---|
| Изменяемая последовательность элементов по порядку | `list` |
| Неизменяемая «запись» фиксированной формы или составной ключ словаря | `tuple` |
| Быстрая проверка `x in ...` и хранение только уникальных элементов | `set` |
| Быстрый поиск значения по ключу | `dict` |

## Проверить понимание

Почему код ниже вызовет ошибку `TypeError`, и как исправить ключ, не меняя
смысла данных?

```python
routes = {}
routes[["GET", "/health"]] = "ok"
```

<details>
<summary>Разбор</summary>

Ключом словаря пытаются сделать список `["GET", "/health"]`. Список —
изменяемый тип, поэтому он нехешируем (`TypeError: unhashable type:
'list'`). Достаточно заменить список на неизменяемый кортеж:
`routes[("GET", "/health")] = "ok"`.

</details>
