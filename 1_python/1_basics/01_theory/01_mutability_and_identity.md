# Изменяемость и идентичность объектов

В Python каждое значение — это объект, у которого есть три свойства: идентичность (identity), тип (type) и значение (value). Тип и идентичность неизменны на протяжении жизни объекта, а вот значение может быть изменяемым (mutable) или неизменяемым (immutable) — это ключевое разделение встроенных типов.

## Изменяемые и неизменяемые типы

* **Неизменяемые (immutable)**: `int`, `float`, `bool`, `str`, `tuple`, `frozenset`, `bytes`, `None`. После создания значение объекта нельзя изменить — любая «модификация» на самом деле создаёт новый объект.
* **Изменяемые (mutable)**: `list`, `dict`, `set`, `bytearray`, а также пользовательские классы по умолчанию. Содержимое объекта можно менять на месте (in place), не создавая новый объект.

```python
s = "hello"
s += " world"   # создаётся НОВАЯ строка, старая осталась в памяти (если на неё нет ссылок — будет собрана GC)

lst = [1, 2, 3]
lst.append(4)   # изменяется ТОТ ЖЕ список, id(lst) не меняется
```

## `is` против `==`

* `==` сравнивает **значения** (вызывает `__eq__`).
* `is` сравнивает **идентичность** — по сути, `id(a) == id(b)`, то есть «это один и тот же объект в памяти».

```python
a = [1, 2, 3]
b = [1, 2, 3]
a == b   # True  — значения равны
a is b   # False — это два разных объекта в памяти
a is a   # True
```

Идиома `x is None` (а не `x == None`) используется именно потому, что `None` — синглтон: в интерпретаторе существует ровно один объект `None`, и сравнение идентичности быстрее и надёжнее (некоторые объекты могут переопределить `__eq__` так, что `obj == None` даст неожиданный результат).

## Кэширование мелких объектов в CPython (implementation detail)

CPython в целях оптимизации кэширует некоторые неизменяемые объекты:

* **Small int caching**: целые числа в диапазоне `[-5, 256]` — это заранее созданные синглтоны.
* **String interning**: короткие строки, похожие на идентификаторы (буквы, цифры, `_`), могут переиспользоваться интерпретатором.

```python
a = 100
b = 100
a is b   # True — оба указывают на закэшированный int

x = 1000
y = 1000
x is y   # False (обычно) — вне диапазона кэша, это два разных объекта
```

> ⚠️ Это деталь реализации CPython, а не гарантия языка. Другие реализации (PyPy, Jython) вправе вести себя иначе. **Никогда не полагайтесь на `is` для сравнения чисел или строк** — используйте `==`. `is` предназначен для сравнения идентичности объектов (например, `is None`, `is True`), а не для проверки равенства значений.

## Алиасинг (aliasing) и ловушки изменяемости

Поскольку переменная в Python — это просто имя, ссылающееся на объект, присваивание не копирует данные:

```python
original = [1, 2, 3]
alias = original       # alias — это ещё одно имя для ТОГО ЖЕ объекта
alias.append(4)
print(original)        # [1, 2, 3, 4] — изменение видно через оба имени!
```

Чтобы получить независимую копию изменяемого объекта, нужно явно копировать (`list(original)`, `original[:]`, `copy.copy`, `copy.deepcopy` для вложенных структур).

## Классическая ловушка: изменяемое значение по умолчанию

Значения параметров по умолчанию вычисляются **один раз**, в момент определения функции, а не при каждом вызове. Если в качестве default указан изменяемый объект, он становится общим состоянием между всеми вызовами:

```python
def add_item(item, bucket=[]):   # bucket создаётся ОДИН раз при импорте модуля
    bucket.append(item)
    return bucket

add_item("a")   # ['a']
add_item("b")   # ['a', 'b']  — тот же список, а не новый!
```

Правильный паттерн — использовать `None` как сентинел и создавать новый изменяемый объект внутри функции:

```python
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

## Почему неизменяемость упрощает рассуждение о коде

* Неизменяемый объект нельзя случайно испортить через альтернативную ссылку — его можно свободно передавать между функциями и потоками (см. подробнее про потокобезопасность в модуле `5_concurrency`).
* Неизменяемые объекты можно безопасно использовать как ключи словаря и элементы множества — это разбирается подробно в [02_hashability_and_performance.md](./02_hashability_and_performance.md).
* Функции, работающие с неизменяемыми данными, легче тестировать: нет скрытых побочных эффектов через общие ссылки.
