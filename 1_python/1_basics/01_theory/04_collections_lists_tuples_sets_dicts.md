# Списки, кортежи, множества, словари

Четыре базовые встроенные коллекции Python отличаются не только синтаксисом, но и внутренним устройством, что определяет их производительность и уместность применения.

## `list` — изменяемый динамический массив

Список реализован как динамический массив указателей на объекты (не как связный список). Это значит:

* доступ по индексу `lst[i]` — O(1);
* добавление в конец `append()` — O(1) амортизированно: CPython выделяет память с запасом (over-allocation), поэтому не каждый `append` требует реального перевыделения памяти;
* вставка/удаление в начало или середину (`insert(0, x)`, `del lst[0]`) — O(n), так как приходится сдвигать все последующие элементы;
* проверка `x in lst` — O(n), линейный перебор (см. [02_hashability_and_performance.md](./02_hashability_and_performance.md)).

```python
lst = [1, 2, 3]
lst.append(4)      # O(1) амортизированно
lst.insert(0, 0)    # O(n) — сдвигает все элементы
```

### Ловушка: `list * n` с вложенными изменяемыми объектами

```python
row = [0] * 3
grid = [row] * 3          # ловушка: все три строки — ОДИН И ТОТ ЖЕ список!
grid[0][0] = 1
print(grid)                # [[1, 0, 0], [1, 0, 0], [1, 0, 0]] — изменилось везде

grid_ok = [[0] * 3 for _ in range(3)]   # правильно: каждая строка — новый список
```

`[row] * 3` копирует **ссылку** на `row` три раза, а не создаёт три независимых списка.

## `tuple` — неизменяемая упорядоченная последовательность

Кортеж фиксированного размера, создаётся один раз и не может быть изменён после создания. За счёт неизменяемости:

* кортеж может быть ключом словаря / элементом множества, **если все его элементы тоже хешируемы**;
* кортежи обычно немного компактнее списков в памяти (нет резерва на рост);
* кортеж уместен для «записи» с фиксированной структурой (например, координата `(x, y)`), тогда как список — для однородной последовательности переменной длины.

```python
point = (10, 20)
cache = {(10, 20): "значение в этой точке"}   # OK, кортеж хешируем

bad = ([1, 2], "label")
# {bad: "..."}   # TypeError — кортеж содержит список, значит сам нехешируем
```

## `set` — хеш-таблица без значений (только ключи)

Множество хранит уникальные хешируемые элементы без гарантии порядка (в CPython порядок зависит от хешей и истории вставок/удалений — не полагайтесь на него). Основное применение — быстрая проверка принадлежности и дедупликация:

```python
seen = set()
unique_ids = []
for event_id in incoming_ids:
    if event_id not in seen:      # O(1) в среднем
        seen.add(event_id)
        unique_ids.append(event_id)
```

## `dict` — хеш-таблица «ключ → значение»

С Python 3.7 порядок вставки ключей **гарантированно** сохраняется при переборе (`for k in d`) — это официальная гарантия языка, а не деталь реализации (в 3.6 было деталью CPython, с 3.7 — часть спецификации). Тем не менее словарь остаётся хеш-таблицей: доступ по ключу `d[key]` — O(1) в среднем, а не позиционный.

### Ловушка: перезапись при совпадении ключей

Если при построении словаря (буквально или через `dict()`/comprehension) встречаются повторяющиеся ключи, побеждает **последнее** значение — предыдущее молча теряется:

```python
d = {"a": 1, "a": 2}
print(d)   # {'a': 2}

pairs = [("x", 1), ("x", 2), ("y", 3)]
result = dict(pairs)
print(result)   # {'x': 2, 'y': 3}
```

## Когда что использовать

| Нужно | Используйте |
|---|---|
| Изменяемая последовательность произвольной длины | `list` |
| Неизменяемая «запись» фиксированной структуры, возможный ключ словаря | `tuple` |
| Быстрая проверка принадлежности, уникальность, без порядка | `set` |
| Отображение «ключ → значение» с быстрым доступом по ключу | `dict` |
