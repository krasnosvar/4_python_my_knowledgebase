# `*args` и `**kwargs`

Обычная функция принимает заранее известное число параметров. Но иногда
нужна функция, которая принимает **любое** количество аргументов: как
`print()`, которому можно передать сколько угодно значений. Для этого есть
`*args` и `**kwargs`. Без них не написать универсальный декоратор
(см. [04_decorators_basics.md](./04_decorators_basics.md)) — поэтому они
идут раньше декораторов.

## Механика упаковки

При объявлении функции `*args` собирает все «лишние» позиционные аргументы
в **кортеж (tuple)**, а `**kwargs` — все «лишние» именованные аргументы в
**словарь (dict)**:

```python
def f(*args, **kwargs):
    print(args)    # tuple
    print(kwargs)  # dict

f(1, 2, a=3, b=4)  # (1, 2)  {'a': 3, 'b': 4}
```

Имена `args`/`kwargs` — соглашение, а не требование языка: важны именно
символы `*` и `**`. Их можно сочетать с обычными параметрами:

```python
def total(first, *rest):
    result = first
    for x in rest:
        result += x
    return result

total(1)          # 1
total(1, 2, 3)    # 6
```

## Позиционные-только и именованные-только параметры (PEP 570)

Символы `/` и `*` в сигнатуре функции задают границы:

```python
def f(a, b, /, c, d, *, e, f):
    ...
```

* параметры до `/` — **только позиционные** (нельзя передать как `a=1`);
* параметры после `*` — **только именованные** (нельзя передать
  позиционно);
* параметры между `/` и `*` — обычные, можно и так, и так.

Позиционные-только параметры полезны, когда имя параметра — деталь
реализации, которую не хочется фиксировать как часть публичного контракта
(так устроены встроенные функции вроде `len(obj, /)`). Именованные-только
параметры делают вызов самодокументируемым и защищают от путаницы порядка
похожих аргументов: `connect(host, port, *, timeout=30)` не даст случайно
передать таймаут позиционно.

## Распаковка при вызове

Тот же синтаксис работает и в обратную сторону — для распаковки готового
кортежа или словаря в аргументы вызова:

```python
args = (1, 2)
kwargs = {"a": 3, "b": 4}
f(*args, **kwargs)  # эквивалентно f(1, 2, a=3, b=4)
```

Так аргументы передают «как есть» дальше — в обёртке декоратора или, в
классах, в метод родительского класса через `super().__init__(*args,
**kwargs)` (что это значит — в разделе
[4_oop](../../4_oop/README.md); пока достаточно знать, что это тот же приём
«пробросить всё дальше»).

## Почему `**kwargs` обязателен для «прозрачного» декоратора

Декоратор — функция, которая оборачивает другую функцию (подробно — в
[04_decorators_basics.md](./04_decorators_basics.md)). Если обёртка
принимает только конкретные, заранее известные аргументы, она перестаёт
работать с функциями другой сигнатуры:

```python
def bad_decorator(func):
    def wrapper(x):       # жёстко зашитый один аргумент
        return func(x)
    return wrapper
```

Такая обёртка сломает любую функцию с двумя аргументами или именованными
параметрами. Чтобы обёртка работала с функцией **любой** сигнатуры, она
должна вслепую принимать и пробрасывать всё через `*args, **kwargs`:

```python
def good_decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```

Это стандартный шаблон любого универсального декоратора (логирование,
тайминг, retry, кэширование) — он будет встречаться почти в каждом примере
дальше.
