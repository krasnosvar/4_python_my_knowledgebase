# `yield from` и подгенераторы

`yield from` делегирует итерацию вложенному iterable или генератору, экономя ручной цикл и корректно прокидывая не только значения, но и исключения/`send`/возвращаемое значение.

## Наивный вариант без `yield from`

```python
def flatten_naive(nested):
    for group in nested:
        for item in group:
            yield item
```

Работает, но это только «прокидывание значений». Если внутренний генератор поддерживает `send()`/`throw()`/имеет `return`-значение — вручную протащить это через ручной цикл сложно и многословно.

## С `yield from`

```python
def flatten(nested):
    for group in nested:
        yield from group
```

`yield from group` делает три вещи одновременно:

1. Перебирает `group` и отдаёт наружу каждое его значение — как обычный `for` + `yield`.
2. Если во внешний генератор придёт `send(value)` или `throw(exc)`, пока он «внутри» `yield from group` — Python перенаправит это **напрямую во внутренний генератор `group`**, а не в приостановленную функцию-обёртку.
3. Когда `group` — генератор и завершается через `return value`, всё выражение `yield from group` **возвращает это `value`** как результат выражения (это то самое `StopIteration.value`, о котором шла речь в предыдущем файле).

## Пример: значение из `return` подгенератора

```python
def inner():
    yield 1
    yield 2
    return "готово"

def outer():
    result = yield from inner()
    print("inner вернул:", result)
    yield 3

list(outer())
# выведет "inner вернул: готово"
# вернёт [1, 2, 3]
```

Без `yield from` пришлось бы вручную ловить `StopIteration` из `inner()` и доставать `.value` — именно это исторически и происходило до появления `yield from` в Python 3.3.

## Типичные применения

* **Flatten** вложенных структур произвольной глубины (списки списков, дерево категорий) — рекурсивный генератор с `yield from` на себя же.
* **Композиция пайплайнов** — разбить сложную генерацию данных на несколько генераторных функций и объединить их без ручных циклов.
* **Делегирование корутин** на основе генераторов (до `async`/`await`) — вызывающий генератор мог прозрачно делегировать работу вложенному, включая `send`/`throw`.

```python
def flatten_deep(nested):
    for item in nested:
        if isinstance(item, list):
            yield from flatten_deep(item)  # рекурсивное делегирование
        else:
            yield item

list(flatten_deep([1, [2, 3, [4, 5]], 6]))  # [1, 2, 3, 4, 5, 6]
```
