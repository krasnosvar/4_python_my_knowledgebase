# Модуль `itertools`

`itertools` — набор ленивых строительных блоков для работы с итераторами: все функции возвращают итераторы, а не списки, и не потребляют вход раньше, чем это действительно нужно.

## `chain` — склеить несколько iterable в один проход

```python
from itertools import chain

log1 = ["a", "b"]
log2 = ["c", "d"]

for line in chain(log1, log2):
    print(line)   # a b c d — без создания промежуточного объединённого списка
```

Полезно, когда нужно обработать несколько источников (например, несколько файлов логов) единым циклом, не склеивая их заранее через `+`.

## `islice` — «срез» итератора без полного потребления

Обычный слайсинг (`data[2:5]`) не работает на итераторах — у них нет индексации. `islice` даёт то же самое поведение лениво:

```python
from itertools import islice

def numbers():
    n = 0
    while True:
        yield n
        n += 1

first_five = list(islice(numbers(), 5))          # [0, 1, 2, 3, 4]
page_2 = list(islice(numbers(), 10, 20))          # элементы с 10 по 19
```

Важно: `islice` не «перематывает» итератор назад — она подряд забирает элементы до нужной границы. Для пагинации это означает, что каждый следующий `islice(it, start, stop)` на **уже использованном** итераторе продолжит с того места, где остановился предыдущий вызов, а не начнёт заново с начала.

## `groupby` — группировка **только соседних** одинаковых ключей

Частая ошибка: считать, что `groupby` группирует все элементы с одинаковым ключом по всей последовательности, как `GROUP BY` в SQL. На самом деле `groupby` группирует только **подряд идущие** элементы с одинаковым ключом:

```python
from itertools import groupby

data = ["a", "a", "b", "a"]
for key, group in groupby(data):
    print(key, list(group))
# a ['a', 'a']
# b ['b']
# a ['a']       <- снова 'a', отдельной группой!
```

Если нужна настоящая группировка по ключу независимо от порядка — данные нужно предварительно **отсортировать по этому же ключу**:

```python
data = sorted(data)
for key, group in groupby(data):
    ...
# теперь все 'a' будут в одной группе
```

Ещё одна тонкость: объект `group`, возвращаемый `groupby`, — это ленивый итератор, привязанный к текущей позиции внешнего итератора. Если не потребить `group` до перехода к следующей итерации внешнего цикла, его содержимое станет недоступно — поэтому `group` нужно сразу материализовать (`list(group)`), если результат нужен не сиюминутно.

## `tee` — размножить один итератор на несколько независимых

```python
from itertools import tee

it = iter([1, 2, 3, 4])
it_a, it_b = tee(it, 2)

print(next(it_a))   # 1
print(list(it_b))    # [1, 2, 3, 4]
```

Важный нюанс: после `tee` **исходный** итератор `it` использовать напрямую нельзя — вся дальнейшая работа идёт только через `it_a`/`it_b`. Кроме того, если один из «клонов» продвигается сильно вперёд другого, `tee` вынужден буферизовать все элементы между их позициями в памяти — при сильно разной скорости потребления это может свести на нет экономию памяти, ради которой обычно используют итераторы.

## Бесконечные итераторы: `count`, `cycle`, `repeat`

```python
from itertools import count, cycle, repeat

counter = count(start=10, step=2)     # 10, 12, 14, 16, ... бесконечно
looper = cycle(["a", "b", "c"])        # a, b, c, a, b, c, ... бесконечно
repeater = repeat("x", times=3)        # x, x, x — конечный вариант с limit
```

Использовать их напрямую в `for` без `break`/`islice` — верный способ зациклить программу навсегда; обычно их комбинируют с `islice` или `zip` с конечным итерируемым.

## Комбинаторика: `product`, `permutations`, `combinations`

```python
from itertools import product, permutations, combinations

list(product([1, 2], ["a", "b"]))     # [(1,'a'), (1,'b'), (2,'a'), (2,'b')] - декартово произведение
list(permutations([1, 2, 3], 2))       # все упорядоченные пары без повторов
list(combinations([1, 2, 3], 2))       # все неупорядоченные пары без повторов
```

Все три ленивы, но их итоговое число комбинаций растёт очень быстро (факториально/экспоненциально) — материализовывать их в список стоит только при заведомо маленьком входе.
