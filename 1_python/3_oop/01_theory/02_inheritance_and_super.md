# Наследование и `super()`

## Одиночное наследование и переопределение

```python
class Animal:
    def __init__(self, name: str) -> None:
        self.name = name

    def speak(self) -> str:
        return "..."

class Dog(Animal):
    def speak(self) -> str:
        return "Гав!"
```

`Dog` наследует все атрибуты и методы `Animal` и может переопределить любой из них. Поиск атрибута идёт снизу вверх: сначала в `Dog`, затем в `Animal`, затем в `object`.

## Что на самом деле делает `super()`

Частое заблуждение: «`super()` вызывает родительский класс». Это неточно. `super()` возвращает **прокси-объект**, который ищет метод в **следующем классе по MRO (Method Resolution Order)** относительно текущего класса — а не обязательно в непосредственном родителе.

```python
class Dog(Animal):
    def __init__(self, name: str, breed: str) -> None:
        super().__init__(name)  # делегирует инициализацию по цепочке MRO
        self.breed = breed
```

При одиночном наследовании разница незаметна: «следующий по MRO» и «родитель» совпадают. Но как только в игру вступает множественное наследование ([03_mro_and_mixins.md](./03_mro_and_mixins.md)), `super()` может передать вызов классу, который не является прямым предком текущего — а «братом» по дереву наследования. Именно поэтому `super()` называют «кооперативным диспетчером», а не «вызовом родителя».

## Почему `super().__init__()` важен даже без множественного наследования

Три причины писать `super().__init__(...)` всегда, а не только когда наследование множественное:

1. **Будущая расширяемость.** Если позже класс станет частью иерархии с миксинами, код уже будет корректным без переписывания.
2. **Явная инициализация базового состояния.** Пропуск `super().__init__()` — частая причина `AttributeError` на атрибутах, которые «должен был» проинициализировать родитель.
3. **Совместимость с кооперативной моделью Python.** Каждый класс в цепочке отвечает только за свою часть инициализации и делегирует остальное дальше по MRO — это позволяет комбинировать независимо написанные классы.

## Переопределение vs расширение поведения

Переопределение (override) полностью заменяет метод. Часто нужнее **расширение**: вызвать поведение родителя и что-то добавить:

```python
class LoggingDog(Dog):
    def speak(self) -> str:
        result = super().speak()
        print(f"[log] {self.name} says {result!r}")
        return result
```

Это идиома, эквивалентная вызову родительской реализации в других языках (`base.Method()` в C#, `super.method()` в Java) — но в Python она обязательно проходит через MRO, а не напрямую к «родителю».
