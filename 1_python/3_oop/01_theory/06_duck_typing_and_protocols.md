# Утиная типизация, ABC и Protocol

## Утиная типизация (duck typing)

«Если это выглядит как утка и крякает как утка — это утка». В Python объект годится для использования, если у него есть нужные методы/атрибуты — **вне зависимости от того, от какого класса он унаследован**. Это философия языка с самого начала, задолго до появления системы типов.

```python
class Duck:
    def quack(self) -> str:
        return "Кря!"

class Person:
    def quack(self) -> str:
        return "Я притворяюсь уткой"

def make_it_quack(thing) -> str:
    return thing.quack()  # неважно, что за тип — важно, что есть .quack()

make_it_quack(Duck())    # Кря!
make_it_quack(Person())  # Я притворяюсь уткой
```

Утиная типизация — неявная, полностью на этапе выполнения. Долгое время у Python не было способа выразить такой контракт статически. Есть два инструмента, решающих это по-разному: `abc.ABC` и `typing.Protocol`.

## `abc.ABC` — номинальная типизация

`abc.ABC` + `@abstractmethod` требуют **явного наследования** и не дают создать экземпляр, пока все абстрактные методы не реализованы:

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...

class Circle(Shape):
    def __init__(self, radius: float) -> None:
        self.radius = radius

    def area(self) -> float:
        return 3.14159 * self.radius ** 2

# Shape()       # TypeError: Can't instantiate abstract class Shape with abstract method area
```

Это **номинальная типизация**: принадлежность к контракту определяется явным объявлением (`class Circle(Shape)`), а не структурой класса. Контракт проверяется Python'ом в момент создания экземпляра (`TypeError`, если метод не реализован).

## `typing.Protocol` — структурная типизация (PEP 544)

`Protocol` описывает контракт **по форме**, без требования явного наследования:

```python
from typing import Protocol

class HasArea(Protocol):
    def area(self) -> float: ...

def print_area(shape: HasArea) -> None:
    print(shape.area())
```

Любой класс с методом `area() -> float` подходит под `HasArea` — включая классы, написанные до появления самого протокола, сторонние классы из библиотек, простые объекты без общего предка:

```python
class Square:  # никак не связан с HasArea, никакого наследования
    def __init__(self, side: float) -> None:
        self.side = side

    def area(self) -> float:
        return self.side ** 2

print_area(Square(4))  # ок для статического анализатора (mypy/pyright) и в рантайме
```

Это и есть формализация утиной типизации: `Protocol` не требует объявленной связи, только совпадение по форме («структуре»). Проверка происходит статически (инструментами типа `mypy`), а не в рантайме, как у `ABC`.

## Когда что использовать

| | `abc.ABC` | `typing.Protocol` |
|---|---|---|
| Тип совместимости | номинальная (по объявлению) | структурная (по форме) |
| Нужно наследование | да | нет |
| Проверка | в рантайме, при инстанцировании | статически, инструментами типизации |
| Подходит для | контролируемая иерархия внутри своего кода, где важно явно закрепить контракт | внешние/сторонние классы, слабая связанность, интерфейсы в духе Go (`interface{}` с неявной реализацией) |

Практическое правило: если вы владеете всей иерархией и хотите явно навязать контракт — берите `ABC`. Если нужно принять «что угодно, что имеет нужную форму» (включая объекты из чужого кода) — `Protocol` гибче и меньше связывает код.
