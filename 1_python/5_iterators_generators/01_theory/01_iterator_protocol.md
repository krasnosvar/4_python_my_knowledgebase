# Протокол итератора

В основе циклов `for` в Python лежит не магия языка, а два простых протокола,
которые может реализовать любой объект.

## Iterable vs Iterator

Это разные вещи, и путаница между ними — источник большинства ошибок:

* **Iterable (итерируемый объект)** — объект, у которого есть метод
  `__iter__()`, возвращающий итератор. Список, кортеж, строка, множество,
  словарь — всё это iterable, но не итераторы.
* **Iterator (итератор)** — объект, у которого есть **оба** метода:
  * `__iter__()` — возвращает **себя** (`return self`);
  * `__next__()` — возвращает следующее значение или бросает `StopIteration`,
    когда значения закончились. «Бросает» значит выбрасывает исключение — сигнал
    «элементов больше нет»; что такое исключения и как их ловят через
    `try`/`except` — см.
    [1_python_fundamentals/06_exceptions](../../1_python_fundamentals/06_exceptions/README.md).

```python
numbers = [1, 2, 3]

it = iter(numbers)      # вызывает numbers.__iter__() -> получаем итератор
print(next(it))          # вызывает it.__next__() -> 1
print(next(it))          # 2
print(next(it))          # 3
next(it)                  # StopIteration
```

Список — iterable, но не итератор: у него нет `__next__`. Каждый вызов
`iter(numbers)` создаёт новый независимый итератор с собственной позицией.

## Как на самом деле работает `for`

Конструкция

```python
for x in numbers:
    print(x)
```

это синтаксический сахар над:

```python
_it = iter(numbers)
while True:
    try:
        x = next(_it)
    except StopIteration:
        break
    print(x)
```

Отсюда следует важный вывод: `for` не требует, чтобы объект был
последовательностью с индексами — ему достаточно протокола
`__iter__`/`__next__`. Это позволяет писать бесконечные потоки данных, сетевые
сокеты, генераторы и т.д., которые не имеют «длины» и индексации, но прекрасно
работают в `for`.

## Итератор — одноразовый

Итератор хранит внутреннее состояние (обычно — текущую позицию). Как только
итератор исчерпан, он остаётся исчерпанным навсегда, повторный проход не даст
элементов:

```python
it = iter([1, 2, 3])
print(list(it))   # [1, 2, 3]
print(list(it))   # [] — итератор уже пуст
```

Именно поэтому у итератора `__iter__` возвращает `self`, а не новый итератор:
итератор *является* самим собой итерируемым объектом, только «одноразовым». Если
нужно пройтись по данным повторно — нужен новый вызов `iter()` на исходном
iterable (для списка это тривиально, для генератора — уже нет, генератор после
первого прохода исчерпан навсегда).

> Частый вопрос на собеседовании: чем итератор отличается от итерируемого
> объекта? Итерируемый объект **умеет создавать** итераторы (через `__iter__`),
> а итератор **хранит состояние** прохода и **потребляется** по мере вызовов
> `next()`.

## Собственный итератор

Любой класс, реализующий оба метода, работает в `for`, `list()`, распаковке,
генераторных выражениях — везде, где ожидается iterable:

```python
class Countdown:
    def __init__(self, start: int) -> None:
        self.current = start

    def __iter__(self) -> "Countdown":
        return self

    def __next__(self) -> int:
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1


for n in Countdown(3):
    print(n)   # 3 2 1
```
