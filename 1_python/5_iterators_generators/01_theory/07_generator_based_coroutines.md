# Генераторы как псевдо-корутины (`send`)

До появления `async`/`await` (PEP 492, Python 3.5) генераторы использовались как
примитивная форма корутин — функций, которые можно приостанавливать и
**возобновлять с передачей значения внутрь**, а не только забирать из них
значения наружу.

## `send()` — это `next()`, только с «входящим» значением

```python
def accumulator():
    total = 0
    while True:
        value = yield total   # получает то, что прислали через send()
        total += value

acc = accumulator()
next(acc)          # обязательный "прайминг": довели генератор до первого yield, получили 0
print(acc.send(10))  # total += 10 -> печатает 10
print(acc.send(5))   # total += 5  -> печатает 15
```

## Почему обязателен «прайминг» (priming)

Сразу после создания генератор ещё не дошёл ни до одного `yield` — его
выполнение не начиналось вообще. Выражение `value = yield total` не может
получить `value` до тех пор, пока не выполнится (и не приостановится на) сама
строка с `yield`. Поэтому первый вызов должен быть либо `next(acc)`, либо
`acc.send(None)` — это ровно то же самое: они доводят генератор до первой точки
остановки, ничего не «отправляя» осмысленного внутрь.

Вызов `acc.send(10)` на **свежесозданном**, ещё не прайм-нутом генераторе —
ошибка (`TypeError: can't send non-None value to a just-started generator`),
потому что там ещё нет активного `yield`, готового принять значение.

## Зачем это знать сегодня

В современном коде такие генераторы почти не пишут вручную — их вытеснил
`async`/`await`, построенный поверх того же самого механизма приостановки
выполнения. Но:

* понимание `send`/`yield`-выражения объясняет, откуда взялась модель
  «сопрограмм» в Python вообще;
* `async def` функции — не генераторы, а отдельный тип объектов (нативные
  корутины): их нельзя перебрать в `for` или передать в `next()`. Но под капотом
  они используют тот же механизм приостановки и возобновления выполнения, а цикл
  событий (event loop) продвигает их вызовом, по сути эквивалентным `send()`, —
  вместо вас.
