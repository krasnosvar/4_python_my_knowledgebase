# Генераторы и `yield`

Писать класс с `__iter__`/`__next__` вручную ради простого перебора — избыточно.
Генератор — способ получить итератор, написав обычную функцию.

## Функция с `yield` — это не функция

Если тело функции содержит хотя бы один `yield`, вызов такой функции **не
выполняет тело**. Вместо этого Python возвращает объект-генератор — готовый
итератор, который умеет запускать тело функции пошагово:

```python
def counter():
    print("старт")
    yield 1
    print("между yield")
    yield 2
    print("конец")

gen = counter()   # тело ещё НЕ выполнилось, ничего не напечаталось
print(next(gen))  # печатает "старт", возвращает 1
print(next(gen))  # печатает "между yield", возвращает 2
next(gen)          # печатает "конец", затем StopIteration
```

## Что происходит при каждом `next()`

Каждый вызов `next()` выполняет код **от текущей точки до ближайшего `yield`**
(или до конца функции). При этом:

* значение, переданное в `yield`, становится результатом `next()`;
* выполнение **приостанавливается** ровно на этой строке — весь стек локальных
  переменных и позиция инструкции сохраняются;
* следующий `next()` возобновляет выполнение сразу после `yield`, как будто
  функция никогда не «замирала».
* если функция доходит до `return` (или до конца тела без `return`) — бросается
  `StopIteration` (значение `return` кладётся в `StopIteration.value`, это
  использует `yield from`, см. следующий файл).

Это и есть главное отличие от обычной функции: обычная функция теряет весь стек
при возврате, генератор — сохраняет его между вызовами. По сути генератор — это
корутина (функция, которую можно приостанавливать и возобновлять; подробно — в
[07_generator_based_coroutines.md](./07_generator_based_coroutines.md)) с ручным
управлением через `next()`.

## Генератор — тоже одноразовый итератор

Генератор сам реализует протокол итератора (`__iter__` возвращает себя,
`__next__` продолжает выполнение). Из этого следует то же правило, что и для
обычных итераторов: пройти по генератору дважды нельзя — второй `for` по уже
исчерпанному генератору не даст элементов.

## `send`, `close`, `throw`

Помимо `next()`, у генератора есть три менее известных метода:

* **`gen.send(value)`** — возобновляет генератор, а `value` становится
  результатом выражения `yield` внутри тела (не результатом `next`, а тем, что
  стоит слева от `yield`, если есть присваивание: `x = yield ...`). Первый вызов
  должен быть `send(None)` — эквивалент `next()`, так как ещё некуда «слать»
  значение, генератор ещё не дошёл до первого `yield`.
* **`gen.close()`** — бросает `GeneratorExit` внутри генератора в точке
  остановки; используется для явной остановки и освобождения ресурсов (например,
  если внутри был `try/finally` с закрытием файла).
* **`gen.throw(exc)`** — бросает исключение `exc` внутри генератора в точке
  остановки, как будто оно возникло прямо на месте `yield`.

Подробнее про `send()` и генераторы как псевдо-корутины — в файле
[07_generator_based_coroutines.md](./07_generator_based_coroutines.md).

## Почему это важно на практике

Генератор не хранит весь результат в памяти — он хранит только «где я
остановился». Это делает генераторы естественным инструментом для потоковой
обработки данных, о чём подробнее в
[04_laziness_and_memory.md](./04_laziness_and_memory.md).
