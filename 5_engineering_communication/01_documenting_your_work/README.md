# Тема 01. Как документировать свою работу

## Зачем этот раздел

Хорошо сделанная, но плохо описанная работа выглядит менее ценной, чем есть на самом деле. Тема учит описывать результат по схеме «проблема → решение → эффект»: в отчёте о проекте, самооценке за период, апдейте для команды. После неё вы сможете за несколько минут превратить «занимался X» в конкретное описание с измеримым эффектом.

**Уже знакомы с темой?** → [CHEATSHEET.md](../CHEATSHEET.md#01-документирование-работы) — раздел этой темы в общей шпаргалке.

## Что нужно знать заранее

Технических предварительных знаний не нужно — тему можно проходить в любой
момент. Полезно держать в голове одну-две свои реальные рабочие или учебные
ситуации, чтобы примерять материал на них.

## Файлы темы

- [01_theory/README.md](./01_theory/README.md) — теория: структура «проблема → решение → эффект», как избегать расплывчатых формулировок, как показывать влияние вместо списка технологий, как подстраивать детализацию под читателя.
- [02_practice/README.md](./02_practice/README.md) — практика: чек-лист и
  сценарии для самостоятельной отработки.

## Как проходить

1. Прочитайте теорию в [01_theory/](./01_theory/README.md).
2. Пройдите чек-лист из [02_practice/](./02_practice/README.md) на своей
   реальной ситуации.
3. Разберите сценарии: сначала письменно сформулируйте свой ответ, потом
   сверьтесь с подсказкой по подходу.

## Когда двигаться дальше

Когда описание любой своей недавней задачи проходит чек-лист из `02_practice/` без исправлений — переходите к [02_explaining_technical_work](../02_explaining_technical_work/).
