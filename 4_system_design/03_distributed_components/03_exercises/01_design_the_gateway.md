# Упражнение 01: спроектировать API Gateway

## Сценарий

Компания строит систему из сервисов `catalog-service`, `orders-service`, `payments-service`, доступных двум типам клиентов: мобильное приложение и партнёрское B2B API (внешние компании интегрируются по контракту). Сейчас у разработчиков идёт спор:

- Один инженер предлагает встроить бизнес-правило «партнёрам старше 1 года сотрудничества — скидка 5% на все заказы» прямо в API Gateway, «раз он всё равно видит все запросы партнёров».
- Второй предлагает, чтобы `payments-service` полностью доверял заголовку `X-User-Id`, который прокидывает Gateway, не проверяя его сам — «Gateway ведь уже проверил токен».
- Третий считает, что мобильному приложению и партнёрскому API нужны настолько разные форматы ответов (мобильному — компактный агрегированный JSON, партнёрам — полный, версионированный по контракту), что это должно решаться на уровне самого Gateway через параметр запроса.
