корректность, в галерее — объёмы и перекос read:write.

## Два кейса рядом

| | Денежные переводы | Галерея изображений |
| :--- | :--- | :--- |
| Доминирует | корректность: не потерять и не задвоить | read-heavy, read:write ≈ 1000:1 |
| Жертвуем | доступностью и параллелизмом | строгой консистентностью на пути чтения |
| Центральное решение | идемпотентность + double-entry + ACID | метаданные отдельно от байтов, асинхронная обработка, CDN |
| Брокер | outbox: надёжная доставка события о свершившемся факте | вынести CPU-bound обработку из пути ответа |
| Источник истины → производное | `ledger_entries` → `balance_minor` | оригинал в blob storage → варианты и CDN-копии |
| Ключ шардирования | `account_id` | `owner_id` |

## Паттерны

| Паттерн | Суть | Когда |
| :--- | :--- | :--- |
| Idempotency key | клиент шлёт UUID в `Idempotency-Key`; сервер на повтор возвращает сохранённый результат | любая операция через ненадёжную сеть |
| Double-entry bookkeeping | каждая операция — пара DEBIT/CREDIT; баланс = сумма записей | деньги, аудируемость |
| Outbox | событие пишется в таблицу `outbox` той же транзакцией; фоновый процесс публикует в брокер | событие не должно потеряться после коммита |
| Saga | цепочка локальных транзакций с компенсирующими действиями, статус `pending`, воркер докручивает | кросс-шардовый / межсервисный перевод |
| Reconciliation | периодическая сверка своих записей с выпиской провайдера | внешний платёжный провайдер |
| Presigned URL | клиент грузит байты прямо в blob storage, backend только координирует | большие загрузки |
| Chunked upload | докачка по частям | нестабильная мобильная сеть |
| Content-addressed storage | объект адресуется хэшем содержимого, дубликаты — новая ссылка | дедупликация на петабайтах |
| Подписанные CDN-URL с TTL | доступ проверяется, ссылка истекает | приватный или платный контент |

Идемпотентность (в реальности — таблица `idempotency_keys` с уникальным ключом):

```python
results = {}  # в реальности — таблица idempotency_keys с уникальным ключом

def transfer(idempotency_key, amount):
    if idempotency_key in results:
        return results[idempotency_key]   # повтор: тот же ответ, без списания
    result = {"status": "completed", "amount": amount}  # здесь ACID-транзакция
    results[idempotency_key] = result
    return result

print(transfer("abc-123", 500) is transfer("abc-123", 500))  # True
```

Деньги — целые минорные единицы, инвариант двойной записи:

```python
print(0.1 + 0.2 == 0.3)   # False — float копит ошибки округления
print(10 + 20 == 30)      # True — копейки в int точны

entries = [("T1", "A", "DEBIT", 500), ("T1", "B", "CREDIT", 500)]
debits = sum(a for _, _, d, a in entries if d == "DEBIT")
credits = sum(a for _, _, d, a in entries if d == "CREDIT")
print(debits == credits)  # True
```

## Денежные переводы: ключевые решения

Подробнее: [01_money_transfers.md](./01_theory/01_money_transfers.md)

| Этап роста | Решение |
| :--- | :--- |
| Старт | один PostgreSQL, ACID, уникальный индекс на `Idempotency-Key` |
| Рост чтения | read-реплики для `GET /balance`, `GET /transfers`; проверка баланса перед списанием — только мастер ⚠️ |
| Рост объёма | шардирование `ledger_entries` по `account_id`; межшардовый перевод — сага |
| Внешний провайдер | передать idempotency key провайдеру + reconciliation |

| Узкое место | Решение |
| :--- | :--- |
| Горячий счёт (мерчант), contention на `SELECT ... FOR UPDATE` | короткие транзакции, очередь на счёт, разбиение на подсчета |
| Окно неопределённости саги | статус `pending`, воркер докручивания, идемпотентность каждого шага |
| Потеря события после коммита | outbox |
| Повторный вызов провайдера | idempotency key на стороне провайдера, сверка |

## Галерея изображений: ключевые решения

Подробнее: [02_image_gallery.md](./01_theory/02_image_gallery.md)

Оценка нагрузки (10 млн загрузок в сутки, 3.5 MB на фото с вариантами):

```python
uploads_per_day = 10**7
seconds_per_day = 10**5          # ~86 400, округлено для оценки
read_write_ratio = 1000
print(uploads_per_day / seconds_per_day)                     # 100.0 — write QPS
print(uploads_per_day * read_write_ratio / seconds_per_day)  # 100000.0 — read QPS
print(uploads_per_day * 3.5 / 10**6, "TB/сутки")             # 35.0 TB/сутки (~12.8 PB/год)
```

| Узкое место | Решение |
| :--- | :--- |
| Большие файлы, обрывы сети | presigned URL напрямую в blob storage + chunked upload |
| Синхронная генерация превью | событие `UploadCompleted` → брокер → воркер-процессы (CPU-bound, GIL) |
| Повторные просмотры бьют по origin | CDN перед blob storage — обязателен |
| Метаданные не влезают в одну БД | шардирование `images` по `owner_id` |
| Дубликаты файлов | content-addressed storage |

Статусы изображения: `uploading → processing → ready | failed`.
Варианты: `thumbnail`, `medium`, `original` (WebP/AVIF).

## Типичные ошибки

- ⚠️ Деньги во `float` вместо целых минорных единиц.
- ⚠️ Полагаться только на ACID: она не защищает от повторной отправки клиентом.
- ⚠️ Публиковать событие в брокер отдельным вызовом после коммита → событие теряется.
- ⚠️ Проверять баланс перед списанием на реплике.
- ⚠️ Хранить байты изображений в реляционной БД.
- ⚠️ Генерировать превью синхронно в HTTP-обработчике.
- ⚠️ Пытаться максимизировать все требования сразу вместо выбора доминирующего.
