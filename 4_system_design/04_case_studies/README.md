# 04. Case Studies (Разбор кейсов целиком)

Два полных разбора системы от требований до эволюции по мере роста нагрузки: денежные переводы (строгая консистентность, идемпотентность, double-entry bookkeeping) и галерея изображений / медиа-хранилище (разделение метаданных и байтов, асинхронная обработка, CDN). Это сборка всех предыдущих разделов базы (`01_architecture_styles`, `02_performance_and_scaling`, `03_distributed_components`) в единый навык — разбор системы целиком, а не отдельной концепции. Теория подкреплена runnable-примерами на чистом Python и упражнениями в формате сценариев дальнейшего роста системы.

## Структура раздела

*   **[01_theory/](./01_theory/)** — полные разборы и синтез:
    *   [01_money_transfers.md](./01_theory/01_money_transfers.md) — денежные переводы: требования → идемпотентность → double-entry bookkeeping → API → модель данных → high-level дизайн → эволюция по нагрузке → узкие места.
    *   [02_image_gallery.md](./01_theory/02_image_gallery.md) — галерея изображений: требования → оценка нагрузки → разделение метаданных/байтов → асинхронный пайплайн обработки → CDN → эволюция по нагрузке → узкие места.
    *   [03_common_patterns.md](./01_theory/03_common_patterns.md) — что общего в методологии и решениях обоих разборов, и как переносить этот подход на новую задачу.
*   **[02_examples/](./02_examples/)** — runnable-примеры на чистом Python (без внешних зависимостей, детерминированные, завершаются сами):
    *   [01_idempotent_transfer](./02_examples/01_idempotent_transfer/main.py) — идемпотентный перевод с double-entry bookkeeping: повторный запрос с тем же ключом не удваивает списание, баланс — производная от журнала движений.
    *   [02_image_pipeline_dedup](./02_examples/02_image_pipeline_dedup/main.py) — пайплайн изображения: разделение метаданных и байтов, асинхронная генерация вариантов, дедупликация по хэшу содержимого.
*   **[03_exercises/](./03_exercises/)** — сценарии дальнейшего роста системы (не код): новое требование или кратный рост нагрузки для одного из двух разобранных кейсов.
    *   `01_transfer_growth` — эволюция системы переводов: периодические переводы, два внешних провайдера, 50-кратный рост с эффектом локальности.
    *   `02_gallery_growth` — эволюция галереи: приватные альбомы, живая совместная лента, 10-кратный пиковый всплеск загрузок, счётчик просмотров.
*   **[04_exercises_answers/](./04_exercises_answers/)** — разобранные рассуждения по тем же сценариям.

## Как проходить тему

1. Разберите оба кейса-эталона целиком: [01_money_transfers.md](./01_theory/01_money_transfers.md) и [02_image_gallery.md](./01_theory/02_image_gallery.md) — они показывают методологию системного дизайна в действии на двух принципиально разных по доминирующему требованию задачах.
2. Прочитайте синтез в [03_common_patterns.md](./01_theory/03_common_patterns.md), чтобы увидеть, что в этих разборах общего и как переносить подход на новую задачу.
3. Запустите и изучите примеры из `02_examples/`:
   ```bash
   python3 ./02_examples/01_idempotent_transfer/main.py
   python3 ./02_examples/02_image_pipeline_dedup/main.py
   ```
4. Проработайте сценарии дальнейшего роста в `03_exercises/` письменно, прежде чем заглядывать в разбор.
5. Сверьте свои рассуждения с [04_exercises_answers/](./04_exercises_answers/).
