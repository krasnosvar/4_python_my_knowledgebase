# Упражнения: architecture styles

Каждая задача — это сценарий, а не код: описание ситуации и вопросы, на которые нужно ответить письменно, обосновав выбор (компромиссы, а не единственный «правильный» ответ). В `04_exercises_answers/` — не готовый шаблонный ответ, а разобранное рассуждение, с которым стоит сверить свою логику, а не только финальный вывод.

## Список задач (от простого к сложному)

1. `01_startup_monolith_or_microservices.md` — стартап на 4 разработчика выбирает архитектуру для нового продукта: монолит или микросервисы, и почему.
2. `02_spot_the_distributed_monolith.md` — по описанию существующей системы определить, является ли она распределённым монолитом, и указать конкретные признаки.
3. `03_migration_plan.md` — составить план инкрементальной миграции конкретного монолита на сервисы через strangler fig, включая порядок выноса модулей.
4. `04_team_topology_fit.md` — подобрать архитектуру под заданную структуру команд и обосновать выбор через призму закона Конвея.
