# Упражнение 01: найти узкое место

## Сценарий

API-эндпоинт `GET /api/v1/dashboard` под нагрузочным тестированием (Locust, ступенчатый рост RPS) показывает такие метрики при 300 req/s:

| Звено пути запроса | p50 latency | p99 latency | Утилизация |
|---|---|---|---|
| Load balancer | 1 мс | 3 мс | 15% |
| Приложение (бизнес-логика) | 8 мс | 15 мс | 40% |
| Redis (кэш агрегатов) | 1 мс | 4 мс | 20% |
| PostgreSQL (запрос при промахе кэша) | 45 мс | 900 мс | 92% |
| Внешний API курсов валют | 60 мс | 70 мс | 10% |

Известно дополнительно: hit ratio кэша Redis для этого эндпоинта — 65%, то есть 35% запросов идут в PostgreSQL. При росте нагрузочного теста до 400 req/s p99 у PostgreSQL подскакивает до 4 секунд, у остальных звеньев — почти не меняется.
