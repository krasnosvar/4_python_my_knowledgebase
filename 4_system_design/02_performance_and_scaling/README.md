# Тема 02. Производительность и масштабирование (Performance and Scaling)

## Зачем этот раздел

Как искать узкие места на уровне системы, а не кода, как методологически профилировать путь запроса целиком, где в архитектуре ставить кэш, когда масштабировать вертикально, а когда горизонтально, и как концептуально шардировать данные, когда один узел БД перестаёт справляться. Теория подкреплена runnable-примерами на чистом Python и упражнениями в формате сценариев системного дизайна.

**Уже знакомы с темой?** → [CHEATSHEET.md](./CHEATSHEET.md) — узкие места, золотые сигналы, уровни кэша, вертикаль vs горизонталь, стратегии шардирования.

## Что нужно знать заранее

- Тема [01_architecture_styles](../01_architecture_styles/).
- Понятие GIL и CPU-bound/I/O-bound нагрузки из
  [5_concurrency](../../1_python/5_concurrency/), базовый SQL и Redis как
  кэш из [2_data_and_messaging](../../2_data_and_messaging/).

## Структура раздела

*   **[01_theory/](./01_theory/)** — теория, разбитая по подтемам:

    *   [02_system_profiling.md](./01_theory/02_system_profiling.md) — методология профилирования системы: где мерить (границы компонентов), что мерить (золотые сигналы), распределённый трейсинг, нагрузочное тестирование.

    *   [04_horizontal_vs_vertical_scaling.md](./01_theory/04_horizontal_vs_vertical_scaling.md) — горизонтальное vs вертикальное масштабирование, закон Амдала, что легко/сложно масштабируется горизонтально.
    *   [05_partitioning_sharding.md](./01_theory/05_partitioning_sharding.md) — партиционирование и шардирование данных на концептуальном уровне: стратегии выбора ключа, consistent hashing, последствия кросс-шардовых запросов и транзакций.
    *   [06_use_cases.md](./01_theory/06_use_cases.md) — практические применения: порядок работы над производительностью, типичные ошибки, мини-чеклист.

    *   [03_consistent_hashing](./02_examples/03_consistent_hashing/main.py) — сравнение наивного `hash(key) % N` и consistent hashing при добавлении шарда: сколько ключей приходится перемещать.
*   **[03_exercises/](./03_exercises/)** — сценарии системного дизайна (не код): описание ситуации и вопросы для письменного разбора.
    *   [01_find_the_bottleneck](./03_exercises/01_find_the_bottleneck.md) — найти реальное узкое место по метрикам пути запроса.
    *   [02_scale_out_or_up](./03_exercises/02_scale_out_or_up.md) — выбрать между вертикальным и горизонтальным масштабированием для двух разных компонентов.
    *   [03_shard_the_dataset](./03_exercises/03_shard_the_dataset.md) — выбрать ключ шардирования и оценить последствия для типичных запросов.
    *   [04_cache_layers_design](./03_exercises/04_cache_layers_design.md) — расставить уровни кэша под продукт с разной степенью персонализации контента.

## Как проходить

1. Прочитайте теорию по подтемам в [01_theory/](./01_theory/), начиная с [01_bottlenecks.md](./01_theory/01_bottlenecks.md).
2. Запустите и изучите примеры из `02_examples/`:
   ```bash
   python3 ./02_examples/01_bottleneck_pipeline/main.py
   python3 ./02_examples/02_scaling_tradeoffs/main.py
   python3 ./02_examples/03_consistent_hashing/main.py
   ```
3. Проработайте сценарии в `03_exercises/` письменно, прежде чем заглядывать в разбор.
4. Сверьте свои рассуждения с [04_exercises_answers/](./04_exercises_answers/).

## Когда двигаться дальше

Когда по метрикам пути запроса можете найти узкое место, объяснить закон Амдала и выбрать ключ шардирования с учётом типичных запросов — переходите к [03_distributed_components](../03_distributed_components/).
