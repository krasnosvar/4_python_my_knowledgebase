# System Design Knowledge Base

Этот раздел — личная база для системного изучения System Design применительно к Python-бэкенду: архитектурные стили, производительность и масштабирование, компоненты распределённой системы и разбор кейсов целиком.

System Design — по большей части язык-агностичная дисциплина: компромиссы монолита и микросервисов, узкие места, кэширование, шардирование, API Gateway, консистентность данных устроены одинаково вне зависимости от языка реализации. Акцент здесь — на том, как эти решения ложатся на Python-стек (GIL и его последствия для CPU-bound масштабирования, FastAPI/Django, Celery/RQ как типичные фоновые воркеры), и на практике, применимой в реальных сервисах и на собеседованиях.

## Эталон структуры

Каждая подтема наполняется по единому стандарту базы:

- краткая теория по подтемам (без воды, с компромиссами и конкретными числами, где это уместно);
- runnable-примеры на чистом Python, где код уместен и полезен для иллюстрации механики;
- упражнения в формате сценариев системного дизайна — не готовые ответы, а разобранные рассуждения для сверки.

## Подразделы

1. [01_architecture_styles](01_architecture_styles/) — архитектурные стили: монолит, микросервисы, распределённый монолит как антипаттерн, критерии выбора под команду и продукт, миграция через strangler fig.
2. [02_performance_and_scaling](02_performance_and_scaling/) — производительность: поиск узких мест, методология профилирования системы, кэширование на уровне архитектуры, горизонтальное vs вертикальное масштабирование, партиционирование и шардирование данных.
3. [03_distributed_components](03_distributed_components/) — компоненты распределённой системы: API Gateway, БД в распределённой системе и полиглот-персистентность, роль брокеров сообщений, алгоритмы балансировки нагрузки, health checks и service discovery.
4. [04_case_studies](04_case_studies/) — разбор кейсов целиком: денежные переводы (идемпотентность, консистентность) и галерея изображений/медиа-хранилище (загрузка, обработка, CDN, метаданные), от требований до эволюции по нагрузке.

## Как проходить

- Идти по порядку от `01_architecture_styles` к `04_case_studies`: как раскладывать систему по границам процессов → как сделать её быстрой и масштабируемой → из каких компонентов она физически состоит → как всё это складывается в разбор реальной системы целиком.
- Раздел 01 — фундамент: выбор архитектурного стиля определяет, какие проблемы вообще встанут перед остальными разделами.
- Раздел 02 — как система ведёт себя под нагрузкой и как её разгружать/масштабировать.
- Раздел 03 — из каких инфраструктурных компонентов состоит уже выделенная распределённая система.
- Раздел 04 — сборка всего вместе на двух сквозных кейсах, разобранных от требований до эволюции по нагрузке.

> Раздел зеркалит по духу аналогичный раздел System Design в Go-версии базы (`3_go_my_knowledgebase/3_system_design`) — те же принципы, тот же уровень рассуждения, адаптированные и переформулированные под Python-стек и под собственный список подтем.
