# Kafka: consumer-группы

Consumer сам по себе просто читает партиции. **Consumer-группа** — это несколько
consumer'ов, которые объединены общим `group_id` и совместно разбирают партиции
topic'а, не пересекаясь друг с другом.

Правило одно и оно жёсткое: **в рамках одной группы одну партицию читает не
более одного consumer'а одновременно**. Это то, что даёт горизонтальное
масштабирование чтения без дублирования обработки внутри группы.

```
Topic "orders" (4 партиции), группа "billing-service" (2 consumer'а):

  P0    P1    P2    P3
   │     │     │     │
   └──┬──┘     └──┬──┘
      │           │
 ┌────▼───┐  ┌────▼───┐
 │Consumer1│  │Consumer2│
 └────────┘  └────────┘

  Consumer1 читает P0 и P1, Consumer2 читает P2 и P3.
  Ни одна партиция не читается двумя consumer'ами сразу.
```

Отсюда прямое следствие для планирования capacity: **число активных consumer'ов
в группе, приносящих пользу, ограничено числом партиций**. 4 партиции и 6
consumer'ов в группе — 2 consumer'а будут простаивать (idle), у Kafka просто нет
для них партиций. Поэтому число партиций планируют исходя из ожидаемого
максимума параллелизма чтения, а не только из throughput на запись.

**Rebalancing.** Когда consumer присоединяется к группе или выходит из неё
(упал, задеплоился заново, завис на обработке дольше `max.poll.interval.ms`),
группа перераспределяет партиции между оставшимися consumer'ами.

```
Было: 2 consumer'а, 4 партиции — по 2 партиции на каждого.

Добавили Consumer3 → REBALANCE:
  P0→C1   P1→C2   P2→C3   P3→C1 (например)

Consumer2 упал → REBALANCE:
  P0→C1   P1→C3   P2→C3   P3→C1

Во время rebalance обработка приостанавливается (stop-the-world для группы),
поэтому слишком частые рестарты consumer'ов или слишком долгая обработка одного
батча (что триггерит kick из группы по таймауту) — это ощутимая эксплуатационная
проблема, а не мелочь.
```

Разные группы полностью независимы друг от друга: группа `analytics` и группа
`notifications`, подписанные на один и тот же topic, читают его каждая
по-своему, не мешая друг другу и не деля партиции между собой — это два
параллельных потока чтения одного и того же лога.
