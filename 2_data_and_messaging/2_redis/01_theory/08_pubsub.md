# Pub/Sub — коротко

Pub/Sub (`PUBLISH`/`SUBSCRIBE`) — механизм "разослать сообщение всем
подписанным прямо сейчас":

```
Publisher → PUBLISH "notifications:user:100" "у вас новое сообщение"
                          │
              Redis рассылает всем текущим подписчикам канала
                          │
              ┌───────────┼───────────┐
              ▼           ▼           ▼
          Подписчик 1  Подписчик 2  (никого нет — сообщение
          получает     получает      просто теряется, Redis
          немедленно   немедленно    его нигде не хранит)
```

Это **fire-and-forget**: если в момент `PUBLISH` подписчиков нет — сообщение
исчезает безвозвратно, история не сохраняется, гарантий доставки нет никаких.
Это уместно только там, где сама природа данных делает "потерять и не заметить"
приемлемым: индикатор "собеседник печатает", live-обновление счётчика на
дашборде, широковещательное уведомление об инвалидации локального кеша на других
инстансах приложения (см.
[05_cache_invalidation.md](./05_cache_invalidation.md)) — если инстанс временно
недоступен, для него это не критично, он и так не мог показать пользователю
устаревший UI, пока был недоступен.

Полноценное сравнение Pub/Sub с persistent-очередями и брокерами сообщений
(Kafka/RabbitMQ), consumer groups, гарантии доставки — предмет отдельного
модуля базы знаний про брокеры сообщений, здесь эта тема сознательно не
раскрывается глубже.
