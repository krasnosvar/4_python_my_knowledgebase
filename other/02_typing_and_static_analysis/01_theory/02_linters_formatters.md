# Линтеры и форматтеры: ruff, black

## Зачем статический анализ, помимо типов

mypy проверяет **типы**. Линтеры и форматтеры решают другие задачи:

- **Линтер** — находит проблемы в коде без его исполнения: неиспользуемые
  импорты и переменные, потенциальные баги (сравнение через `is` с
  литералом, изменяемый аргумент по умолчанию `def f(x=[])`), нарушения
  стиля (PEP 8), небезопасные конструкции.
- **Форматтер** — приводит форматирование (отступы, длина строк, кавычки,
  пробелы) к единому стандарту **автоматически**, убирая из code review
  споры о стиле как класс.

## Ruff — линтер (и не только)

Ruff — быстрый (написан на Rust) линтер, объединивший функциональность
десятка более старых инструментов (flake8 + большинство его плагинов,
isort, pyupgrade и т.д.) в один бинарник:

```bash
ruff check .            # проверить проект
ruff check . --fix       # автоматически исправить то, что можно исправить безопасно
ruff format .             # ruff умеет и форматирование (алгоритм, совместимый с black)
```

Конфигурация — в `pyproject.toml`:

```toml
[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]   # pycodestyle, pyflakes, isort, pyupgrade, bugbear
ignore = ["E501"]                       # длина строки — отдельно решается форматтером
```

## Black — форматтер ("uncompromising")

```bash
black .              # переформатировать все файлы
black --check .        # только проверить, ничего не меняя (для CI)
black --diff .          # показать, что изменилось бы
```

Философия Black — **минимум настроек**: почти всё форматирование
детерминировано и не обсуждается (одна из немногих настроек — длина
строки). Это осознанный компромисс: команда тратит время на код, а не на
холивары про расстановку запятых.

Ruff умеет форматировать в стиле, совместимом с Black (`ruff format`) — на
2026 год многие проекты используют **только Ruff и для линта, и для
формата**, отказываясь от отдельного Black, чтобы не держать два
инструмента с пересекающейся ответственностью.

## Типичный набор для нового проекта

```toml
[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM"]

[tool.mypy]
python_version = "3.12"
strict = true
```

```bash
ruff format .
ruff check . --fix
mypy src/
```

## pre-commit: запускать проверки автоматически

Чтобы не полагаться на память разработчика, линтер/форматтер/тип-чекер
обычно подключают как git hook через `pre-commit`:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
```

```bash
pre-commit install        # один раз на клоне репозитория
pre-commit run --all-files  # прогнать вручную на всех файлах
```

После этого `ruff`/`ruff format` запускаются автоматически при каждом
`git commit` (см.
[../../0_tooling_and_workflow/01_git_essentials/01_theory/03_conflicts_and_hygiene.md](../../0_tooling_and_workflow/01_git_essentials/01_theory/03_conflicts_and_hygiene.md)
про commit hygiene) — код, не проходящий проверки, просто не закоммитится.
