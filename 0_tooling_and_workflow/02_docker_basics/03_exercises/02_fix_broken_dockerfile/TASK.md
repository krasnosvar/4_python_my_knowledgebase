# Упражнение 2. Починить сломанный Dockerfile

## Стартовое состояние

В `app/` лежит рабочее Flask-приложение (`main.py`, слушает порт `5000`) и
`requirements.txt`. Рядом лежит `Dockerfile`, который **не собирается или
работает неправильно** — в нём несколько ошибок.

## TODO

- [ ] Запустить `docker build -t exercise-02 .` и посмотреть на ошибку.
- [ ] Найти и исправить **несоответствие имени файла**: приложение называется
      `main.py`, а Dockerfile ссылается на несуществующий `app.py`
      (и в `COPY`, и в `CMD`).
- [ ] Найти и исправить **несоответствие порта**: приложение слушает `5000`,
      а `EXPOSE` в Dockerfile указывает `8000`. Приведите `EXPOSE` в
      соответствие реальному порту приложения.
- [ ] Собрать образ и убедиться, что контейнер запускается и отвечает на
      порту `5000`:
      ```bash
      docker build -t exercise-02 .
      docker run --rm -d -p 5000:5000 --name exercise-02 exercise-02
      curl http://localhost:5000/
      docker stop exercise-02
      ```

## Подсказки

- `EXPOSE` — это только документация порта, который слушает процесс внутри
  контейнера; реальный проброс задаётся флагом `-p` у `docker run`. Но
  документация должна быть верной — иначе тот, кто запускает ваш образ,
  будет пробрасывать не тот порт.
- Правьте только `Dockerfile` — код приложения в `app/` менять не нужно.
