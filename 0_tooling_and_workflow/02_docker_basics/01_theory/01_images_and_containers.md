# Образы vs контейнеры

## Образ (image) — это шаблон, контейнер — это его запущенный экземпляр

- **Образ** — неизменяемый (immutable) набор слоёв файловой системы плюс
  метаданные (какая команда запускается по умолчанию, какие переменные
  окружения и т.д.). Образ ничего не выполняет — это просто данные на диске.
- **Контейнер** — процесс (точнее, набор процессов), запущенный из образа с
  добавлением тонкого **read-write слоя** поверх read-only слоёв образа.
  Из одного образа можно запустить сколько угодно независимых контейнеров.

```bash
docker images          # список образов на машине
docker ps               # список ЗАПУЩЕННЫХ контейнеров
docker ps -a             # список ВСЕХ контейнеров, включая остановленные
```

## Слои (layers) и кэш сборки

Образ состоит из слоёв — каждая инструкция `Dockerfile` (кроме нескольких
метаданных-инструкций вроде `CMD`) создаёт новый слой. Слои кэшируются и
переиспользуются между сборками, пока не изменится сама инструкция **или**
её входные данные (файлы, которые она копирует).

⚠️ Неочевидный, но важный момент: если инструкция N в Dockerfile изменилась —
Docker инвалидирует кэш для неё и **для всех последующих инструкций**, даже
если они не поменялись. Отсюда правило: инструкции, которые меняются редко
(установка системных зависимостей), должны идти **раньше** тех, что меняются
часто (копирование исходного кода приложения). Подробнее — в
[02_dockerfile_basics.md](./02_dockerfile_basics.md).

## Контейнер эфемерен

Файловая система контейнера (read-write слой) живёт вместе с контейнером:

```bash
docker rm <container>     # удаляет контейнер И его read-write слой — данные пропадают
```

Если данные должны переживать перезапуск/удаление контейнера (база данных,
загруженные файлы) — их нужно выносить за пределы этого слоя через **volume**
или bind mount (см. `03_compose_and_commands.md`). Полагаться на то, что
данные "просто останутся" в контейнере — частая ошибка новичков.

## Основные жизненные команды контейнера

```bash
docker run <image>              # создать и запустить контейнер из образа
docker run -d <image>             # в фоне (detached)
docker run -p 8000:8000 <image>   # пробросить порт: host:container
docker run --rm <image>            # удалить контейнер автоматически после остановки

docker stop <container>           # мягко остановить (SIGTERM, потом SIGKILL по таймауту)
docker start <container>           # запустить снова уже существующий (не новый!) контейнер
docker restart <container>

docker exec -it <container> bash   # выполнить команду / зайти в УЖЕ запущенный контейнер
docker logs <container>             # логи контейнера (stdout/stderr процесса с PID 1)
docker logs -f <container>           # follow, аналог tail -f
```

`docker run` vs `docker exec` — частая путаница: `run` создаёт **новый**
контейнер из образа, `exec` запускает дополнительный процесс **внутри уже
существующего** контейнера.

## Именование и очистка

```bash
docker run --name myapp <image>
docker rm myapp
docker rmi <image>                # удалить образ (только если нет контейнеров на его основе)

docker system prune                # убрать неиспользуемые контейнеры/сети/dangling-образы
docker system df                    # сколько места занимают образы/контейнеры/volume'ы
```
