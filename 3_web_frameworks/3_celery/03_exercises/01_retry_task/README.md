# Упражнение 1: задача с retry и экспоненциальным backoff

## Задание

В файле `tasks.py` есть задача `unreliable_call`, которая имитирует
ненадёжный внешний вызов: с вероятностью около 50% бросает `ConnectionError`.

Доработайте задачу так, чтобы:

1. при возникновении `ConnectionError` она автоматически повторялась
   (retry) с экспоненциальной задержкой между попытками;
2. число попыток было ограничено (например, 5 максимум);
3. если все попытки исчерпаны и задача так и не выполнилась успешно —
   финальная ошибка логировалась через `logger.error(...)` с понятным
   сообщением (а не просто падала с необработанным исключением).

Отметки `# TODO` в `tasks.py` показывают, что нужно поправить.

## Как проверить

1. Запустите Redis и worker (можно переиспользовать стенд из `02_examples`,
   но добавив путь к этому модулю в `PYTHONPATH`, либо скопировать
   `celery_app.py`/`tasks.py` из этого упражнения во временную папку —
   проще всего запустить worker локально):

   ```bash
   # из директории 01_retry_task, при поднятом Redis на localhost:6379
   pip install celery redis
   celery -A tasks worker --loglevel=info
   ```

2. В соседнем терминале несколько раз отправьте задачу:

   ```bash
   python -c "from tasks import unreliable_call; r = unreliable_call.delay('demo'); print(r.get(timeout=30))"
   ```

3. Наблюдайте в логе worker-а: часть вызовов должна падать с
   `ConnectionError` и тут же логировать `Retry` с растущей задержкой
   (1s, 2s, 4s, ...), а итоговый вызов — либо завершиться успешно, либо
   (если совсем не повезло за все попытки) залогировать финальную ошибку
   через `logger.error`.
