# Тема 4. Сравнение стеков

## Зачем эта тема

Предыдущие темы разбирали инструменты по отдельности. Здесь — обратная
задача: есть конкретный проект (маленький API, монолит с админкой,
высоконагруженный async-сервис), и нужно выбрать стек и обосновать
выбор. После темы ты сможешь сравнить FastAPI и Django по существу, а не
«по вкусу», и решить, нужен ли проекту Celery.

**Уже знакомы с темой?** → [CHEATSHEET.md](./CHEATSHEET.md) — таблица FastAPI vs Django vs Celery и «проект → стек».

## Что нужно знать заранее

Темы [1_fastapi](../1_fastapi/), [2_django](../2_django/) и
[3_celery](../3_celery/) этого раздела.

## Структура темы

Только теория, без кода — это тема про выбор архитектуры, а не про
конкретный инструмент. Читать по порядку:

1. [01_fastapi_vs_django.md](./01_theory/01_fastapi_vs_django.md) —
   async-first против batteries-included: сильные и слабые стороны.
2. [02_where_celery_fits.md](./01_theory/02_where_celery_fits.md) — где
   в этой картине фоновые задачи.
3. [03_choosing_by_project_type.md](./01_theory/03_choosing_by_project_type.md)
   — критерии выбора под тип проекта.

## Как проходить тему

Проходить последней в разделе, после [1_fastapi](../1_fastapi/),
[2_django](../2_django/) и [3_celery](../3_celery/): сравнение имеет
смысл, только когда каждый инструмент уже пощупан руками.

## Когда двигаться дальше

Когда ты можешь для заданного проекта (маленький API, монолит с админкой,
высоконагруженный async-сервис) выбрать стек и обосновать выбор в двух-трёх
предложениях — раздел пройден. Дальше —
[4_system_design](../../4_system_design/): как отдельные сервисы
складываются в архитектуру целиком.
