# HTTP и первое приложение на FastAPI

Прежде чем разбирать тонкости FastAPI, нужно понимать, с чем он вообще
работает. Веб-сервис — это программа, которая принимает **HTTP-запросы**
по сети и отвечает на них **HTTP-ответами**. Всё остальное в этом
разделе (асинхронность, валидация, зависимости, миграции) — надстройка
над этой простой схемой.

## Что такое HTTP: запрос и ответ

HTTP — текстовый протокол «вопрос — ответ». Клиент (браузер, мобильное
приложение, другой сервис, `curl`) отправляет **запрос**, сервер
возвращает **ответ**. Сервер сам никогда не начинает разговор первым.

Запрос состоит из:

- **метода** — что клиент хочет сделать (`GET`, `POST`, ...);
- **пути** (URL) — с каким ресурсом (`/items/42`);
- **заголовков** (headers) — служебных пар «имя: значение»
  (`Content-Type: application/json`, `Authorization: Bearer ...`);
- **тела** (body) — данных запроса; обычно есть у `POST`/`PUT`, у `GET`
  его, как правило, нет.

Ответ состоит из **статус-кода** (число, коротко сообщающее итог),
заголовков и тела.

Так выглядит обмен «вживую» (упрощённо):

```text
POST /items HTTP/1.1
Host: api.example.com
Content-Type: application/json

{"name": "Чайник", "price": 1500}

HTTP/1.1 201 Created
Content-Type: application/json

{"id": 42, "name": "Чайник", "price": 1500}
```

## Методы

| Метод | Смысл | Пример |
|---|---|---|
| `GET` | получить данные, ничего не меняя | `GET /items/42` |
| `POST` | создать новый ресурс | `POST /items` с телом |
| `PUT` | заменить ресурс целиком | `PUT /items/42` с телом |
| `PATCH` | изменить часть полей ресурса | `PATCH /items/42` |
| `DELETE` | удалить ресурс | `DELETE /items/42` |

Подход, при котором URL обозначает ресурс («товар 42»), а метод — действие
над ним, называется **REST**. Большинство API в этом репо устроены именно
так.

## Статус-коды

Первая цифра — класс ответа: `2xx` — успех, `4xx` — ошибка клиента
(запрос неправильный), `5xx` — ошибка сервера (сломался сам сервис).

| Код | Что значит |
|---|---|
| `200 OK` | успех, данные в теле |
| `201 Created` | ресурс создан (типичный ответ на `POST`) |
| `202 Accepted` | запрос принят, но обработка будет позже (фоновые задачи) |
| `400 Bad Request` | запрос некорректен |
| `401 Unauthorized` | клиент не представился (нет или неверный токен) |
| `403 Forbidden` | клиент известен, но прав на действие нет |
| `404 Not Found` | такого ресурса нет |
| `422 Unprocessable Entity` | данные не прошли валидацию (FastAPI отдаёт его сам) |
| `500 Internal Server Error` | необработанная ошибка в коде сервера |

Частая путаница: `401` — «кто ты?», `403` — «знаю, кто ты, но нельзя».

## Как передаются данные: путь, query, тело, заголовки

- **Path-параметр** — часть пути, идентифицирует ресурс:
  `/items/42` — товар с id `42`.
- **Query-параметры** — после `?`, пары `ключ=значение` через `&`,
  обычно для фильтров и пагинации: `/items?limit=20&skip=40`.
- **Тело в формате JSON** — для сложных данных (создание, изменение).
  JSON выглядит почти как словарь Python: `{"name": "Чайник"}`.
- **Заголовки** — служебная информация: формат данных, токен
  авторизации, язык клиента.

## Что такое веб-фреймворк и роут

Принять сырые байты из сети, разобрать HTTP, вызвать нужный код и
собрать ответ — рутина, которую никто не пишет вручную. **Веб-фреймворк**
делает это за вас: вы пишете только функции-обработчики, а фреймворк
решает, какую из них вызвать.

**Роут** (route, маршрут) — связка «метод + путь → функция». Например,
«`GET /items/{item_id}` → функция `read_item`». Функцию-обработчик роута
ещё называют **эндпоинтом** (endpoint).

## WSGI и ASGI в одном абзаце

Между фреймворком и сетью стоит **сервер приложения** — отдельная
программа, которая слушает порт и передаёт запросы в ваш код. Договор о
том, *как* сервер вызывает код фреймворка, называется интерфейсом.
**WSGI** — старый синхронный интерфейс: один запрос занимает один поток
до конца обработки (так традиционно работает Django, сервер — `gunicorn`).
**ASGI** — его асинхронный преемник: один процесс может обслуживать много
запросов одновременно через `async`/`await` (так работает FastAPI, сервер
— `uvicorn`). Подробнее про `async`/`await` — в
[1_python/5_concurrency](../../../1_python/5_concurrency/).

## Минимальное приложение

```python
# main.py
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def root() -> dict:
    return {"message": "привет"}


@app.get("/items/{item_id}")
def read_item(item_id: int, q: str | None = None) -> dict:
    return {"item_id": item_id, "q": q}
```

Запуск (нужны `pip install fastapi uvicorn`):

```bash
uvicorn main:app --reload
```

`main:app` — «в файле `main.py` взять объект `app`», `--reload` —
перезапускать сервер при изменении кода (только для разработки). После
запуска:

- `http://127.0.0.1:8000/items/42?q=test` вернёт
  `{"item_id": 42, "q": "test"}`;
- `http://127.0.0.1:8000/items/abc` вернёт `422`: `abc` не число;
- `http://127.0.0.1:8000/docs` — автоматически сгенерированная
  интерактивная документация по всем роутам.

`@app.get("/items/{item_id}")` — декоратор (см.
[1_python/2_functions_and_decorators](../../../1_python/2_functions_and_decorators/)),
который регистрирует функцию как обработчик `GET`-запросов на этот путь.
`{item_id}` в пути становится path-параметром, а `q` — параметр функции,
которого нет в пути, — FastAPI считает query-параметром.

## Почему аннотации типов здесь важны

В обычном Python аннотации (`item_id: int`, `-> dict`) — необязательные
подсказки, интерпретатор их не проверяет (см. раздел «Аннотации типов» в
[06_functions_basics](../../../1_python/1_python_fundamentals/06_functions_basics/01_theory/01_functions_basics.md)
и подробно —
[other/02_typing_and_static_analysis](../../../other/02_typing_and_static_analysis/01_theory/01_type_hints_and_mypy.md)).

FastAPI — исключение: он **читает** аннотации и по ним решает, что
делать с запросом. `item_id: int` означает «взять из пути и
преобразовать в `int`, а если не получилось — сразу ответить `422`».
`q: str | None = None` — «необязательный query-параметр». Поэтому в
FastAPI аннотации не украшение, а часть логики: без них фреймворк не
узнает, откуда брать данные и как их проверять. Для сложных данных
(тело запроса) вместо простых типов используются Pydantic-модели —
следующий урок после асинхронности.
